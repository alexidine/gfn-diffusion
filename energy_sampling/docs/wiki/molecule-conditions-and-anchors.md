A *condition* on the crystal route is a molecule: the policy is handed a fixed description of it and asked for a packing. That description is read from files on disk, not from a live encoder. This page covers which keys name those files, what a file must contain, how the QM9-derived sets are built, and which key enters problem identity. The encoder that produced the embeddings is [molecule-encoder](molecule-encoder.md); what training does with a condition is [conditional-route](conditional-route.md); the runtime anchor store is [anchor-buffer](anchor-buffer.md).

## The four keys

Four config keys name the files a run reads; the table lists, for each, the trainer method that loads it and what it becomes.

| key | read by | what it names |
|---|---|---|
| `cfg:molecules_path` | `train.py::Modeller.init_mol_dataset` | the condition set trained over, loaded into `mol_dataset` |
| `cfg:prior_path` | `train.py::Modeller.init_prior_dataset` | the structures backward training draws from, `prior_dataset` |
| `cfg:test_molecules_path` | `train.py::Modeller.init_mol_dataset` | held-out conditions, `test_mol_dataset`; `null` leaves it `None` and every `eval_test` metric absent |
| `cfg:buffers.anchor_buffer.seed_source` | `train.py::Modeller.init_anchor_buffer_seed` | `generated`, `prior_dataset`, or a path loaded the same way |

The envelopes differ. `train.py::Modeller._load_condition_file` unwraps `{'prior': batch}` and is shared by the two condition keys; `init_prior_dataset` reads the `'equalized_prior'` entry; a seed-source path accepts either. The three dataset keys each become a `buffer.py::CrystalBuffer` over one resident collated batch; a seed-source batch is re-scored and handed to the anchor buffer instead. On mk_dev the first two keys name the same file, one molecule, unconditional.

A prior file may also carry `thermal_scaling_factor`: `init_prior_dataset` tests for the key's presence and lets it replace `lj_coeff` for the whole run, raising on a non-unit value beside any `cfg:energy_function` other than `elj`, since the coefficient is applied inside `compute_eLJ_energy` and reaches no other route. That function also wipes `smiles`, keeps `identifier`, calls `buffer.py::strip_lazy_sg_caches`, and runs `train.py::Modeller._verify_dead_latent_rows`.

## What a condition file holds

The full QM9 file is a list of `MolData`, one molecule per row, each carrying `.smiles`. Everything the trainer reads is crystal-shaped: a collated `MolCrystalData` batch of structures carrying cell parameters, `identifier`, `sg_ind`, `z_prime`, `aunit_handedness`, and on the embedding route `embedding`.

Identity resolves through `identifier`. `train.py::Modeller.init_identifiers` collects every `identifier` across the three datasets, sorts them, mints a dense integer `mol_id`, attaches it to all three resident batches, and calls `energies/molecular_crystal.py::MolecularCrystal.set_n_molecules`. Backward training draws from `prior_dataset`, a separately loaded file, and the registry spans both; that the two files carry matching `identifier` fields is assumed, not checked by fingerprint or geometry. `MolecularCrystal.condition_samples` forms `condition_id` as a mixed-radix combination of `mol_id` with the dense-local space group and Z' indices, the library sized `n_molecules * n_sg * n_zp`. A batch with no `mol_id` collapses onto molecule index 0 rather than raising; a side-loaded anchor seed whose identifiers are absent from the registry does raise.

At intake every path re-poses the molecule, `orient_molecule(mode='std')` being called at rollout and at buffer admission while `MolecularCrystal.analyze_crystal_batch` scores with `std_orientation=False`, so a stored molecule has to be a fixed point of that function already; the frame itself is [asymmetric-unit-reduction](asymmetric-unit-reduction.md).

## Handedness at load

The trainer's build never applies a row's stored `aunit_handedness`. `MolecularCrystal.analyze_crystal_batch` scores with `std_orientation=False`, and `mxtaltools/dataset_utils/data_class_methods/crystal_building.py::MolCrystalBuilding.pose_aunit` applies the flag only under `std_orientation=True`. `analyze_crystal_batch` merges `cfg:energy_config.analyze_kwargs` over its keyword defaults after setting them, so the `False` holds while that block carries no `std_orientation` entry; the block is empty on mk_dev. `MolecularCrystal.instantiate_crystals` starts from `MolecularCrystal.init_blank_crystal_batch`, which writes +1, when the energy's computes need the periodic cluster (the pair-sum energies, `elj` among them), and from a clone of the stored row otherwise. Either way a row's crystal is built from its stored molecule as though its handedness were +1. The crystal search's descent, `mxtaltools/crystal_search/crystal_opt_utils.py::gradient_descent_optimization` ([crystal-search-method](crystal-search-method.md)), scores with `std_orientation=True`, under which -1 reflects the molecule's standard frame through $x \to -x$ before the rotation. For a molecule stored at its standard-frame fixed point, the crystal the trainer builds from a -1 row is the crystal the search scored only where that reflection maps the molecule onto itself.

`train.py::Modeller._refuse_mirrored_rows` checks each file as it is loaded, before anything scores it: the `'equalized_prior'` batch in `init_prior_dataset`, both condition files in `init_mol_dataset`, and a seed-source path in `init_anchor_buffer_seed`. It acts only when the energy function's `is_crystal` is true and its `latent_energy` false; the toy and latent-scored energies read the latent and never place the molecule. `train.py::mirrored_rows` reads the handedness columns below each row's $Z'$, collate padding the others with 0. A $Z'=1$ row whose handedness is not +1 raises a `ValueError` naming the config key, the file, the count of such rows and the name held in `train.py::TRAINER_CHART_CONVERSION`, `build_qm9_full_prior.py::to_trainer_chart`. That function rewrites $P\bar{1}$, $Z'=1$ search rows so that the trainer's build reproduces the crystal the search scored: it poses each asymmetric unit as the search scored it, Kabsch-fits the source molecule onto it by a proper rotation, or onto its inversion partner at minus the centroid, within `build_qm9_full_prior.py::FIT_TOL`, sets handedness +1, and moves a centroid with $x > 1/2$ by $-1/2$. A $Z'>1$ row with an active unit whose handedness is not +1 is counted in a printed line, which words the value as -1, and is not refused. The docstring of `train.py::Modeller._refuse_mirrored_rows` records measurements dated 2026-09-30 of the trainer-read eLJ against the stored value on -1 rows of search and prior files.

## The QM9-derived sets

Two QM9 sources exist. `models/encoder_probe.py::load_qm9` reads the full dataset at `QM9_FULL`, which its docstring states as 133,728 molecules with every SMILES distinct; it deduplicates on `smiles` and raises rather than returning fewer than asked. The `qm9c100k_chunk*.pt` files under `QM9_DIR` are crystal anchors: the same docstring records about 5,850 unique molecules across 30 chunks, roughly 4% of QM9, at about 8.2 crystal rows per molecule, and 0.0% of molecules carrying a chiral tag in either source.

`build_qm9_conditions.py` turns a QM9 SG2 crystal dataset into a conditions/prior pair: `normalize_schema` fills the `z_prime` and `aunit_handedness` fields those files leave unset, `select_molecules` keeps whole molecules replica-richest first so a rung is exactly a set of condition ids, `drop_pathological` drops structures whose baked `lj_pot` exceeds `--lj-max`, `reconstruct_parameterization` derives centroid, orientation and handedness from the real coordinates (the CIF-derived files store `pos` at real coordinates and aunit parameters that do not describe it), and `pin_to_trainer_frame` makes the file a fixed point of `orient_molecule(mode='std')`. Molecules whose principal-axis basis is left-handed are mapped by a reflection: they are stored as their mirror image, their `aunit_orientation` cannot be repaired, and they carry `crystal_valid = 0`, counted in the file's `n_crystals_valid` / `n_crystals_total`. A stage with `bwd_sampling_mode: dataset` trains on stored cell parameters, and the script prints that restriction.

## The random-conformer sets

`build_rc_prior.py` writes condition, prior and held-out files from a random-start search over molecules that carry one random conformer each (`data_processing/random_conformers.py`), organised in the chunk families of `build_rc_prior.py::FAMILIES`. A unit is one chunk of one family. `build_rc_prior.py::find_units` admits a unit only when `build_rc_prior.py::run_complete` holds for every seed run of it, and `build_rc_prior.py::process_unit` refuses a seed output whose row count differs from the `n_out` of its progress file.

Identity and side. `build_rc_prior.py::molecule_registry` groups every string of the two selection files written by `data_processing/smiles_mixture.py` by its canonical stereo-free SMILES (`data_processing/smiles_mixture.py::canon`) and records each identifier `<string>_c0` as kept or dropped. It keeps one identifier per canonical molecule (the earliest family in `FAMILIES`, then a string that is already canonical, then the smallest string), drops every identifier outside `qm9rc` whose canonical SMILES is in `data_processing/smiles_mixture.py::qm9_reference`, and marks a molecule held out when any of its strings is held out in either selection file. `build_rc_prior.py::stage_assemble` takes every row's side from the registry and asserts, per family, that no canonical molecule has rows on both sides. `build_rc_prior.py::combine` re-asserts, over the families it joins, one identifier per canonical molecule (by `canon` of each row's `smiles`) and disjoint sides; it does not consult the registry. No side is assigned at random.

Frame. `inn_modeller.py::InnModeller.conditioned` and `inn_modeller.py::InnModeller.fold_condition_crystals` call `orient_molecule(mode='std')` on condition molecules after moving them to the training device. `mxtaltools/crystal_building/utils.py::align_mol_batch_to_standard_axes` rotates by the heavy-atom principal axes of `mxtaltools/common/geometry_utils.py::batch_molecule_principal_axes_torch`, which flips each axis to a non-negative overlap with the unit direction from the heavy-atom centroid to the farthest heavy atom (an exactly zero overlap counts as positive); `mxtaltools/common/geometry_utils.py::correct_Ip_directions` also negates the least-overlap axis when some overlap is below 1e-5 and the basis `torch.linalg.eigh` returned is left-handed. When the heavy atoms are coplanar, the plane normal is orthogonal to the reference direction and its overlap is zero up to rounding; the frame's handedness then rests on the sign of that rounding and on the signs `eigh` returns, both of which depend on the device's arithmetic, and a molecule whose hydrogens leave the plane is mirrored. When the two farthest heavy atoms are nearly equidistant from the centroid, the reference direction itself rests on rounding. `build_rc_prior.py::frame_margins` computes, per molecule, the smaller of the least absolute overlap of a principal axis with the reference direction and the relative gap between the two largest heavy-atom distances from the heavy-atom centroid, and gives 0 to a molecule with fewer than three heavy atoms; `process_unit` leaves out every row of a molecule whose margin is below `--frame-margin` (default 1e-4).

Reductions. Per unit, after dropping rows with a non-finite eLJ, as `build_qm9_full_prior.py` does for its screened chunks: `build_qm9_full_prior.py::_metric_ok`, `build_qm9_full_prior.py::_standardize`, then, per molecule in ascending eLJ, the removal of a crystal within `--dup-cut` envwise RDF distance of one already kept, among crystals in a pair within `--screen-de` eLJ and `--screen-dpc` packing coefficient. The farthest-point selection of `build_qm9_full_prior.py::_fps` is not applied. `build_qm9_full_prior.py::to_trainer_chart` re-describes every survivor in the trainer's chart and leaves out a row the source molecule fits neither copy of within `build_qm9_full_prior.py::FIT_TOL`. `build_rc_prior.py::stage_assemble` then leaves out every row `build_qm9_full_prior.py::density_keep` rejects, a packing coefficient outside the zero region of `energies/molecular_crystal.py::density_penalty` (0.55 to 0.95, `build_qm9_full_prior.py::DENSITY_RULE`), the bound `data_processing/pool_assemble.py` applies to the pooled priors; a molecule left with no row drops out of every file, its carrier included, and each family file records `density_rule` and the counts in its `build` entry. `build_qm9_full_prior.py::stage_assemble` applies the same bound after `to_trainer_chart`, and `build_rc_prior.py::combine` refuses a family file whose `build` entry has no `density_rule`. `build_rc_prior.py::trainer_read_check`, run by `stage_assemble` on each family's prior, asserts that no row is off handedness +1 (`train.py::mirrored_rows`), rebuilds eLJ on 32 random prior rows with `std_orientation=False` and unit `lj_coeff`, and asserts the largest absolute difference from the stored eLJ below `build_rc_prior.py::TRAINER_READ_TOL`. The outputs are one set of files per family; `--combine` joins chosen families into the files a run names, and `--rows-per-molecule` keeps at most that many crystals per molecule in the prior and held-out prior (`build_rc_prior.py::thin_rows`: the carrier and the rest drawn at random, seeded by identifier). `--molecule-fraction` (default 1; `build_rc_prior.py::parse_args` rejects a value outside (0, 1]) keeps, in the conditions and prior files only, the training molecules whose `build_rc_prior.py::molecule_u`, a hash of the identifier keyed apart from the one seeding `thin_rows`, falls below the fraction; the held-out conditions and prior keep every molecule, and a smaller fraction keeps a subset of a larger one's molecules. Each combined file records `molecule_fraction`, `rows_in_file` and `molecules_in_file`.

## The frozen conditioner and the ladder

Molecule conditioning ships as pre-embedded vectors. `build_qm9_conditions.py::embed` and `build_anchor_conditions.py::embed` run a frozen Mo3ENet autoencoder once, offline, and bake `embedding` of shape `[n, 3, bottleneck]` onto each row, equivariant rather than scalarized. Mo3ENet's vocabulary is `{1, 6, 7, 8, 9}`, and both scripts exit on a molecule set carrying any other atom type.

Wiring is three places. `train.py::Modeller.get_conditioning_dim` adds `cfg:embedding_conditioning_dim` to the conditioner's input width while `conditions_type` stays `'vector'`, so the embedding rides the same `mxtaltools/models/modules/components.py::scalarMLP` conditioner a toy `c` does (`models/gfn.py::GFN.init_conditioner`). `MolecularCrystal.condition_samples` reshapes the stored embedding to `[num_graphs, -1]`, raising when the batch has none or the flattened width disagrees with the configured dim. `utils.py::get_problem_definition` writes `emb_cond` and `emb_cond_dim` into problem identity only when the flag is on, so a run that never sets it keeps the identity it had before the key existed.

The ladder as it exists in configs is `configs/qm9_aug11/`, arms `qm9_v1`, `qm9_v2` and `qm9_v8`, each with `embedding_conditioning: true`, `embedding_conditioning_dim: 192`, `energy_config.temperature: 6.9`, and `test_molecules_path` null on the first two and a held-out conditions file on `qm9_v8`. `configs/qm9_aug11/make.py` records the arms as built `--valid-only`, the ladder topping out at 8 molecules, and the mirrored remainder in the held-out file.

## The CSD latent leg and the ELJ anchors

`extract_csd_latents.py` harvests the molecule-agnostic latent distribution for one space group and Z' from the featurized CSD, storing the twelve rows of its `LATENT_NAMES` plus light provenance, and not the crystals. Latents are dimensionless, `latent_transform` dividing cell lengths by molecular radius and using fractional centroids. A latents-only file is not a `prior_path`: that key needs a collated batch with identifiers, since `init_prior_dataset` re-analyzes energies and `init_identifiers` reads the identifier column.

The anchor leg builds structures instead. `prep_qm9_anchor_mols.py` samples molecules from the CSD-free QM9 file, pins them to the `orient_molecule(mode='std')` fixed point and drops those that move; a crystal search optimises them under the house ELJ recipe; `merge_anchor_chunks.py` checks chunk disjointness; `filter_anchors.py` drops `elj > 0` and packing above `--max-packing` (default 0.85), `--min-packing` being off by default; `build_anchor_conditions.py` attaches embeddings and writes the file pair. Embeddings are computed once on the canonical molecules and broadcast to anchors by identifier, so every anchor of a molecule shares a bit-identical condition vector, and the prior carries them too. The conditions file takes one carrier per molecule, the lowest-energy anchor; the prior takes the full set. No `thermal_scaling_factor` is written.

## Splitting on the structural equivalence class

`build_anchor_conditions.py` splits at the SMILES level, not the identifier level: `--holdout-n` distinct SMILES keys are drawn under `--holdout-seed`, every molecule sharing a key moves together, and an assertion checks no SMILES spans the split. The prior is rebuilt from training molecules only; the held-out file carries `"split": "holdout"` and no `equalized_prior` companion, held-out conditions being forward-sampled and never trained on. `build_qm9_full_prior.py::stage_assemble` holds out a `--holdout-frac` share of the distinct SMILES under `--holdout-seed`, writes a conditions file, a prior file and a held-out conditions file in the envelopes `build_anchor_conditions.py` uses, and asserts that the prior and the conditions file carry the same identifiers and that no held-out identifier is among them. It also writes `<tag>_test_prior.pt`, holding every kept crystal of the held-out molecules under both `'prior'` and `'equalized_prior'` with `"split": "holdout"`, and a provenance file; the line it prints pairing files with config keys names `molecules_path`, `prior_path` and `test_molecules_path` for the first three files and no key for these two.

The probe path splits one level coarser. `models/encoder_probe.py::parent_skeleton` strips stereochemistry and returns the canonical SMILES; `encoder_probe.main` groups rows by skeleton, shuffles the groups, emits each group's members contiguously, advances the held-out boundary to the next group edge, and asserts no group spans the split. Its docstring records 67.9% of held-out rows carrying a same-skeleton sibling in training at `n_train = 4000` under a row-wise split, rising 14.0% to 50.5% to 67.9% with `n`. Raw QM9 carries no stereo tags; `load_qm9_stereo` assigns one configuration per molecule at each tetrahedral centre rather than enumerating.

On the conformer route `build_conformer_set.py` splits on the constitution as well, by a salted `blake2b` hash of `build_conformer_set.py::constitution_key` (`parent_skeleton` after explicit hydrogens are removed) rather than by a shuffle, and every stereoisomer it builds is a separate condition on its molecule's side. By default (`--pool-need 0`) it draws from every row of the source except the rows `build_conformer_set.py::plan_split` refuses (unparseable SMILES and duplicate keys); with a positive `--pool-need` or `--pool-from-encoder` it draws from file indices past the encoder's reconstructed pool and refuses rows whose constitution the pool contains; [conformer-conditioning-and-carrier](conformer-conditioning-and-carrier.md) has the build.

## Prior identity

`cfg:prior_path` is a field of `utils.py::get_problem_definition`, beside schema version, energy function, the energy config minus the non-identity list, space groups, Z primes and the conditioning flags. `cfg:molecules_path` and `cfg:test_molecules_path` are not. The field is the configured path string, not the file's content, so two runs whose `prior_path` strings differ have different `utils.py::problem_hash` values and a checkpoint from one is refused by the other on an explicitly named file ([checkpoints-and-resume](checkpoints-and-resume.md)), while two runs that differ only in `cfg:molecules_path` or `cfg:test_molecules_path` have equal problem definitions and equal hashes. `checkpointing.py::Checkpointer.WARM_START_EXEMPTIBLE` is the single exception, `prior_path` alone, usable only through `cfg:warm_start_ignore_problem_keys` on the weights-only path, and it prints what it exempted.

Under `cfg:energy_config.energy_reference: seed_min` the content of the prior, conditions and held-out files enters a check separate from the problem-definition comparison. `train.py::Modeller._seed_min_reference_table` takes, per condition, the minimum seed energy over the prior's rows, the stored crystals of the conditions file, and those of the held-out file when one is loaded ([reward-construction](reward-construction.md)), and raises when a condition of the library has no finite value among them. On a full resume `energies/molecular_crystal.py::resolve_energy_reference` raises when the checkpoint's stored mode differs from the configured one, when the checkpoint's table is absent or differs in shape from the recomputed one, or when their largest absolute difference divided by `cfg:energy_config.temperature` exceeds `energies/molecular_crystal.py::ENERGY_REFERENCE_RESUME_TOL_NATS`.

The auto-discovery that used to consume this is gone. `init_prior_dataset` loads a frozen prior model only when `cfg:prior_model_name` names one; the `reuse_prior` key and the fallback chain through `Checkpointer.find_shared_prior` are deleted from the trainer, with the deletion recorded in place, and `find_shared_prior` itself remains in `checkpointing.py` with no caller. A named prior model is checked with `Checkpointer.assert_problem_match` under `ignore_keys=('mol_cond', 'temp_cond', 'vec_cond')`, the prior being a sampling-only object rebuilt from its own stored `gfn_config` and sampled at its stored `train_T`.

## Could be tooling

A dataset preflight, given a config, would load the three files, print each one's stored metadata (`n_molecules`, `n_crystals_valid`/`n_crystals_total`, `embedding_dim`, `frame`, `holdout_seed`, presence of `thermal_scaling_factor`), and assert what the trainer assumes rather than verifies: `prior_path`'s identifiers a subset of `molecules_path`'s, the test file's intersecting neither, `embedding` present at exactly `cfg:embedding_conditioning_dim` when the flag is on, no two conditions coincident in embedding, and a second `orient_molecule(mode='std')` moving no atom beyond a tolerance. The same preflight could build a sample of each file's rows twice, as the trainer builds them and with the stored handedness applied, and compare the two energies for each combination of the rows' unit handedness values, which covers the $Z'>1$ rows the load check only counts. A second tool belongs at config generation: report which `problem_def` fields differ between two configs, and whether the difference is `prior_path` alone.
