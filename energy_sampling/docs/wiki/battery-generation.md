A *battery* is a set of experimental *arms*, each arm one YAML config that one training process reads. A battery generator is a Python program that starts from a base config, applies per-arm deltas, asserts the result, writes the files, and writes the index and submission script the cluster reads. This page is about that program. Two shapes of it exist in the tree, `configs/generate.py` and the hand-forked `configs/<battery>/make.py`. What a generated config is then checked against is [config-validation](config-validation.md); how the written sbatch is submitted and watched is [cluster-operations](cluster-operations.md); what a seed checkpoint carries into an arm is [checkpoints-and-resume](checkpoints-and-resume.md).

## The library path: `configs/generate.py`

`generate.py::arm` builds one config in a fixed order: the canonical config, then a *problem block*, then the arm's own overrides. `generate.py::canonical` loads `configs/mk_dev.yaml` through `utils.py::load_yaml` and raises `SystemExit` if the file's `project_state_version` differs from `config_state.CURRENT_STATE_VERSION`. `generate.py::problem_block` reads `configs/problems.yaml` through `generate.py::problems`, drops the documentation keys in `generate.py::_PROBLEM_METADATA`, and relocates the two in `generate.py::_PROBLEM_KEY_PATHS` (`temperature` and `analyze_kwargs`, both under `cfg:energy_config`); every other registry key already names its config path.

Overrides arrive as keyword arguments. A name without a dot is deep-merged by `generate.py::merge`, where dicts recurse and scalars and lists replace whole. A dotted name goes through `generate.py::set_dotted`, which walks the path on a copy, creates missing dicts, and accepts a trailing list index so `protocol.stages[0].mle_gate` reaches one stage. It raises rather than guessing in three cases: a path segment that is neither dict nor list, an index past the end of the list, and a dotted name that itself ends in an index. No key is whitelisted; `protocol` and per-stage `loss_coeffs` are overridable like any other.

`generate.py::stamp` then writes a single top-level `provenance` block holding the canonical filename, `canonical_sha` (the first 12 hex digits of a SHA-256 over `mk_dev.yaml`'s bytes), the state version, the problem name and a UTC timestamp. Nothing outside `generate.py` reads that key.

`generate.py::emit` writes each arm to `{name}.yaml`, then validates the *written file* rather than the dict in memory. `generate.py::validate` calls `config_invariants.py::check`: an ERROR raises `SystemExit`, a BASELINE violation is returned and printed. `generate.py::deviations` compares the arm against canonical on the *resolved* configs via `config_snapshot.py::snapshot` and `config_snapshot.py::compare`, provenance stripped from both sides; `config_snapshot.py::snapshot` returns a `load_error` key rather than raising, `config_snapshot.py::compare` carries it through as `Comparison.candidate_error`, and `emit` turns a non-empty `candidate_error` into a `SystemExit` naming the file. `generate.py::_write_index` writes `INDEX.tsv`, columns `name, problem, batch, epochs, state, canonical_sha`.

## The hand-forked path: `configs/<battery>/make.py`

A forked generator is a module with module-level constants for the shape, a builder per arm, a `check` re-asserting the finished dict, and a `main` writing the YAMLs, the index and the sbatch. Forks import each other directly by `importlib.util.spec_from_file_location`: `configs/prod_sep20/make.py` loads `configs/final_sep19/make.py` and mutates its family tables, and `final_sep19` loads `configs/mle_w3_sep16/make.py` for the git and identity helpers.

**Which `mk_dev` is the base.** `final_sep19/make.py::committed_mk_dev` runs `git show HEAD:energy_sampling/configs/mk_dev.yaml` and parses the output, so the base is the committed file and not the working tree. `configs/force_sep18/make.py::base` reads `configs/mk_dev.yaml` from disk. A base need not be canonical at all: `configs/dose_sep16/make.py` sets `BASE` to another battery's arm, `configs/prod_sep12/p12_mip_lr1.yaml`.

**The dirty-tree gate.** `mle_w3_sep16/make.py::dirty_files` runs `git status --porcelain --untracked-files=all` over `energy_sampling/` and reports `configs/mk_dev.yaml` plus any `.py` outside `configs/`, `tests/` and `SCRATCH/`. `final_sep19` and `prod_sep20` print a warning and continue. `dose_sep16/make.py::dirty_files` runs the same query over an explicit `EXECUTED` tuple of ten files and calls `sys.exit` unless `--allow-dirty` is passed.

**`energy_config` and the constructor signature.** `train.py::Modeller.init_energy_function` builds a dict of conditioning and route fields, calls `.update(self.args.energy_config.__dict__)` on it, and splats the result: `MolecularCrystal(**energy_config)`. An `energy_config` key the constructor does not name is a `TypeError`, in every arm that carries it, at model construction. `mle_w3_sep16/make.py::committed_crystal_init` AST-parses the committed `energies/molecular_crystal.py` for `MolecularCrystal.__init__` and returns `{arg: default}`; `check` asserts no `energy_config` key is missing from it, and `align_energy_identity` drops a key the seed arm lacked only when its value equals the committed default, raising otherwise. `final_sep19/make.py::common` copies the keys in its `IDENTITY_KEYS` tuple from the seed YAML whole, absences included; that tuple holds `prior_path`, `molecules_path`, `test_molecules_path`, `space_groups`, `z_primes`, `energy_function`, `mlip_path`, `checkpoints_dir`, `model` and `energy_config`. `utils.py::get_problem_definition` places `energy_config`, minus `utils.py::_NON_IDENTITY_ENERGY_CONFIG_KEYS`, into the definition that `utils.py::problem_hash` hashes.

## The conformer ladder: `configs/conformer_cond/make.py`

`configs/conformer_cond/make.py` is a fork that writes one arm per rung of its `RUNGS` table for the conformer route. `main` reads `configs/conformer_mk.yaml` and `configs/mk_dev.yaml` through `conformer_cond/make.py::git_show`, which runs `git show HEAD:<path>` and raises `SystemExit` when git cannot produce the file. It parses the committed `energies/conformer_torsions.py` and `conformer_modeller.py` with `conformer_cond/make.py::energy_contract`, which returns the `ConformerTorsions.__init__` parameters, `_NON_ENERGY_KEYS` and each parameter's default. `conformer_cond/make.py::dirty_warnings` prints the output of `mle_w3_sep16/make.py::dirty_files`, a modified `configs/conformer_mk.yaml`, and dirty MXtalTools paths containing `conformers`. `conformer_cond/make.py::build` refuses a base that does not select `conformer_conditional_tb`.

`conformer_cond/make.py::build_arm` sets `cfg:tag` to `confc`, `cfg:checkpoints_dir` to `mle_w3_sep16/make.py::CLUSTER_CKPTS` and `cfg:checkpoint_name` to `WARM_CHECKPOINT_PLACEHOLDER`, with `cfg:load_weights_only` and `cfg:continue_from_checkpoint` false. It writes the rung's `max_steps` onto `train_prior`, `conformer_cond/make.py::UPDATE_LOG_Z` onto `tb_conditioning`'s `update_log_z` flag, the rung's `cfg:epochs`, and `conformer_cond/make.py::BUFFER_CAPS`. `cfg:molecules_path` and `cfg:energy_config.internal_prior_path` become absolute paths under `conformer_cond/make.py::CLUSTER_SETS`, and `cfg:prior_path` and `cfg:test_molecules_path` null.

Each rung's data is a set directory `LOCAL_SETS/<set_id>/`, and each entry of `RUNGS` declares its kind with a `validation` flag. `conformer_cond/make.py::rung_smiles` returns `None` for a *training* rung (`validation` false) and the rung's `smiles` tuple for a *validation* rung (`validation` true). It refuses a rung whose `validation` is absent or not a bool, a training rung that names `smiles`, and a validation rung whose `smiles` is not a non-empty list of distinct strings without surrounding whitespace. In `RUNGS`, `r0` is a validation rung over `C`, `CO`, `N`, `CCO`, `C=O` and `CC` in the set directory `val_r0`; `r1` and `r2` are training rungs. A training rung's set is written by `build_conformer_set.py` ([conformer-conditioning-and-carrier](conformer-conditioning-and-carrier.md)), a validation rung's by `build_conformer_conditions.py --manifest` (below).

`conformer_cond/make.py::read_set` reads `CONDITIONS_FILE` (`conditions_train.pt`) and `MANIFEST_FILE` (`manifest.json`). It refuses when either is missing, naming the builder command for the rung's kind. It refuses a manifest whose `format` is not the rung kind's: `MANIFEST_FORMAT` (`conformer_set_v1`) for a training rung and `VALIDATION_MANIFEST_FORMAT` (`conformer_set_hand_picked_v1`) for a validation rung. A manifest of the other kind gets its own message naming both formats. For both kinds it then refuses when the manifest does not list the conditions file with that file's sha256 and byte count, when its train side does not count the rung's `n` molecules in at least `n` conditions, or when it names no RDKit version. It also refuses when `conformer_cond/make.py::energy_kwargs_mismatches` finds a difference between the manifest's energy kwargs and the arm's `cfg:energy_config`. That function compares every `ConformerTorsions` parameter outside `RUN_SURFACE_KEYS`, filling a key absent on either side with the committed default, and it reports any builder key the committed signature lacks. For a validation rung it last refuses when the sorted SMILES of the manifest's train members differ from the rung's sorted `smiles`, or when the number of members differs from the manifest's condition count. The builder's held-out and prior files are not shipped. `build_arm` records the size and sha256 of the conditions file and of the local InternalPrior, and the manifest's RDKit version and train condition count; its result carries `validation`, which `main` prints beside each arm.

`build_conformer_conditions.py --manifest` writes a validation rung's manifest beside `--out`. `build_conformer_conditions.py::clear_manifest` runs before any member is built. It exits when `--carrier`, `--config` or `--encoder-ckpt` is absent, when `--out` is not named `conditions_train.pt` (`::MANIFEST_CONDITIONS_NAME`), and when the directory holds a `manifest.json` whose `format` is anything but `::MANIFEST_FORMAT`, which is the case for a `build_conformer_set.py` set. It deletes a manifest of its own format and creates the directory. `::write_manifest` runs after every other file the run writes. It records the format; the SMILES as given (`requested`); `rungs.train`, with molecules counted by distinct `::constitution_smiles` and conditions counted by member; `members.train`, each member's identifier, SMILES, constitution, `k` and pad count; the refused SMILES with their reason codes; and the energy kwargs the members were built under, which are `--config`'s with any flag override applied. It also records the config's path and sha256, the encoder's sha256 and dimensions, the carrier `K` and region widths, and git HEAD with whether the config matches its HEAD blob (`build_conformer_set.py::_provenance_git`). Last come the library versions, RDKit among them, and the sha256 and size of each file written, keyed by its path relative to the manifest's directory. The SMILES are not filtered against the encoder's training pool, and there is no held-out side. `build_conformer_conditions.py::MANIFEST_FORMAT` equals `conformer_cond/make.py::VALIDATION_MANIFEST_FORMAT`. `tests/config/test_conformer_battery.py::test_the_hand_picked_builder_writes_the_set_a_validation_rung_reads` asserts it, builds the `r0` set with the builder, generates the `r0` arm from it through `build`, and has the same set refused under `r1`.

The run name is set last: `conformer_cond/make.py::arm_name` gives `cc_<rung>_n<M>_<digest>`, where `conformer_cond/make.py::arm_digest` is 8 hex characters of sha256 over the finished config minus `cfg:run_name`, the artifact triples and the RDKit version. Two builds from the same inputs give the same name. A change to any config value, rung setting, data file or RDKit version gives a new one.

`conformer_cond/make.py::check_arm` refuses an arm on any of these, naming the key:
- an `energy_config` key outside the committed contract and `temperature`;
- a key of the committed `mk_dev.yaml` outside `cfg:protocols` that the arm lacks and `CRYSTAL_ONLY_KEYS` does not name (`missing_mk_dev_keys`);
- a local path. `refuse_local_paths` runs `mle_w3_sep16/make.py::_scan_local_paths`, refuses any drive-letter string at any key, and refuses a relative value under `DATA_PATH_KEYS` unless `git cat-file -e` finds it in HEAD;
- a setting other than those `conformer_cond/make.py::check_protocol` asserts. These cover the protocol and stage names, level `full` with `mmff`, `energy_clip`, `cfg:energy_config.stereo_coeff` present and equal to `conformer_cond/make.py::STEREO_COEFF`, `cfg:energy_config.temperature` equal to `10**log_temperature`, the set policy, `cfg:condition_log_z.rollout_condition_draw` `cycle`, the `tb_conditioning` fracs, `fwd_rollout_every`, `freeze_pb` and `balance`, and the `hard_failure` tripwire and backstops. They also cover each branch's effective `tb_conditioning` loss coefficients, the stage override over the base block, against `conformer_cond/make.py::TB_SEAT`;
- rows per condition below `FLOOR_PER_CONDITION`, counted over the manifest's train conditions, where stereoisomers are separate conditions;
- `conformer_cond/make.py::vram_bytes` above `CARD_BYTES` x `cfg:cuda_memory_fraction` x `BUFFER_SHARE`, checked by `conformer_cond/make.py::refuse_over_vram` while `cfg:buffer_device` is `cuda`. `vram_bytes` is `conformer_cond/make.py::store_rows` (the three buffer caps plus `cfg:energy_config.prior_sample_size`) times `conformer_cond/make.py::row_bytes` per store, plus `TABLE_BYTES_PER_CONDITION_MAX` per condition of the set; `row_bytes` is `BYTES_PER_ROW_MAX` for full graph rows and the compact row's bytes at `K_MAX` where `cfg:molecules_path` is set ([conformer-training](conformer-training.md));
- any `config_invariants.py::check` violation, BASELINE included.

It then calls `final_sep19/make.py::load_check`. `conformer_cond/make.py::check_battery` refuses two arms equal apart from `cfg:run_name`, an arm name that is a suffix of another, more than one `cfg:energy_config.energy_clip` across the arms, and a ladder whose `conformer_cond/make.py::sidecar_disk_bytes` sum exceeds `DISK_BUDGET_BYTES`. `sidecar_disk_bytes` counts one frozen sidecar per archive (`cfg:epochs` // `cfg:archive_period`) plus the rolling one, each the prior, anchor and replay buffers at their caps times `row_bytes`, a compact row with `COMPACT_HOST_BYTES_PER_ROW` added. `conformer_cond/make.py::write` removes stale `cc_*.yaml`, writes each arm and asserts that it reads back equal. It writes `INDEX_a.tsv`, whose fifth column is the RDKit version and whose columns from the sixth on are (path under `CLUSTER_SETS`, bytes, sha256) triples, and the sbatch ([cluster-operations](cluster-operations.md)). The module labels `RUNGS`' `phase1_max_steps` and `epochs`, `CARD_BYTES`, `BUFFER_SHARE` and `DISK_BUDGET_BYTES` as working assumptions. `tests/config/test_conformer_canonical_contract.py` holds `configs/conformer_mk.yaml` to `check_protocol`, and to `refuse_over_vram` at `LOCAL_CARD_BYTES`. `tests/config/test_conformer_battery.py` builds from the working-tree canonical files handed to `build` directly, and runs each set refusal on `r0` and on `r1`.

## Arm identity

An arm is defined by its deltas, so a key an arm does not set takes the base's value. Two arms whose specs differ only in a key one of them omits resolve to the same config apart from `run_name`. Nothing in `generate.py::emit` or in the forked `main` functions before `conformer_cond/make.py` compares two emitted arms for equality; the deviation summary compares each arm against canonical, not against its siblings. `conformer_cond/make.py::check_battery` does compare them.

`run_name` is the arm's identity at runtime. `train.py` sets `self.run_name = str(self.args.tag) + '_' + str(self.args.run_name)`, `checkpointing.py::Checkpointer.path_for` builds every checkpoint path from it, and `wandb.init` takes it as `name` with `cfg:tag` as the run's only tag. Two launches under one `run_name` share those paths: `running` is rewritten every 50 steps and `final` unconditionally at exit, including by a launch that trains zero steps (`checkpointing.py::Checkpointer.read_only`, `.archive`). `prod_sep20/make.py::main` unlinks the battery directory's stale `{TAG}_*.yaml` before writing, so a renamed arm leaves no orphan file behind. The crystal forks carry a dated battery prefix in each arm name (`fin19_`, `p20_`), set by hand. `conformer_cond/make.py::arm_name` ends each name in `arm_digest` instead, so an arm regenerated with any change is not handed the old arm's `_running.pt` or `<arm>.dead` sentinel by the sbatch's name globs.

## Loading a written config inside the generator

`final_sep19/make.py::load_check` loads a written YAML inside the generator: it replaces the two fields the sbatch fills in (`cfg:checkpoint_name`, which the generator left at `WARM_CHECKPOINT_PLACEHOLDER`, and `cfg:prior_model_name`, left at `PRIOR_MODEL_PLACEHOLDER`) with a loadable pair, `'SEED_best.pt'` and `None`, runs `config_invariants.errors`, then `utils.py::resolve_derived_config(utils.py::preflight_config(utils.py::dict2namespace(raw)))`, constructs `protocol.py::StageProtocol` and asserts the parsed stage names. `preflight_config` is where a retired key raises `ValueError` naming its replacement, where the state version is checked, and where `cfg:eval_T` is required to equal `cfg:integrator.T`. `config_invariants.py::figs_period_fires` is an ERROR, so `cfg:figs_period` that is not a positive multiple of `cfg:eval_period` fails here rather than silently never firing.

An arm that must load weights only on its first launch and resume in full afterwards leaves `cfg:load_weights_only` at `WEIGHTS_ONLY_PLACEHOLDER`. The sbatch written from `final_sep19/make.py::SBATCH` fills it with `true` in the seed branch and `false` in the resume branches, so a resubmission does not restart the arm at step 0. `load_check` does not replace that field; `nsym_sep30/make.py::main` runs it on the arm with each value before writing the placeholder.

`mle_w3_sep16/make.py::_scan_local_paths` walks the finished config recursively and raises on any string that lowercases to a `c:` or `d:` prefix or contains a backslash. Nothing in `preflight_config` looks at path *shape*, and a machine-local path resolves on the machine that generated it. The scan refuses a `D:\` value before submission. `force_sep18/make.py` does not call it and writes `D:\crystal_datasets\...` sidecar paths into its arms.

## Assertions and cluster fields in a generator

`check` functions re-assert the finished dict rather than trusting the builders. Two subjects recur across the forks. The trajectory length is asserted rather than assumed: `final_sep19/make.py::check_common` and `prod_sep20/make.py::check` assert `cfg:integrator.T` and `cfg:eval_T` are both 100, and `force_sep18/make.py::common` asserts `cfg:integrator.T` is 10 without touching `cfg:eval_T`. `cfg:epochs` is read by `train.py::Modeller.train` as an absolute ceiling on the step counter rather than a run length, so a generator seeding from a checkpoint asserts a floor (`cfg['epochs'] >= 500_000` against `EPOCHS = 1_000_000`) or computes one from the seed step (`RESUME_STEP + STUB_STEPS + steps`).

Cluster fields are set by the generator beside the experiment. `cfg:cuda_memory_fraction` reaches `torch.cuda.set_per_process_memory_fraction` in `train.py` and is 0.97 in `mle_w3_sep16`, 0.75 in `force_sep18`, 0.9 in canonical. `cfg:eval_period`, `cfg:eval_num_samples` and `cfg:figs_period` are set together as a route-dependent dict (`UMA_EVAL`, `ELJ_EVAL` in `final_sep19`). `config_snapshot.py::_ENVIRONMENT_KEYS` holds `checkpoints_dir`, `device`, `cuda_memory_fraction`, `run_name` and `tag`, so a difference in any of them is reported apart from a changed rate. The SLURM wall clock is a module constant (`WALL`) formatted into `#SBATCH --time`, and `#SBATCH --array=0-{last}` is filled from `len(arms) - 1`; the array task id plus 2 indexes a row of `INDEX_{leg}.tsv`.

## Could be tooling

Four checks the generators perform in some places and not others are mechanical enough to live in one module. Sibling comparison: `config_snapshot.compare` already resolves two configs and reports CHANGED, so running it pairwise across a battery would print the keys each pair differs on, and a pair with no non-environment difference is a duplicate arm. The local-path scan and the `energy_config`-against-the-constructor-signature check are implemented once in `mle_w3_sep16/make.py` and reachable only by importing that battery; both are pure functions of a config dict and one AST parse. `load_check` is the step that turns a written file into a file known to load, and each battery restates it with its own placeholder substitutions; a shared version taking the config and the expected stage names would make its absence visible. And given a seed checkpoint path, assert `epochs` exceeds that checkpoint's `step_ind`, which no generator here reads.
