# Conformer training

*Drift: **C** (code-bound). Verified against commit `a637e70`, 2026-09-20. Sources at the end.*

The conformer route samples internal-coordinate states of one molecule, or of a set of molecules, against a classical force field. The chart and the free-degree-of-freedom levels are on [conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md); the force field and the fitted `InternalPrior` are on [conformer-force-field-and-prior](conformer-force-field-and-prior.md); the molecule-conditional path, the carrier state and the set policy are on [conformer-conditioning-and-carrier](conformer-conditioning-and-carrier.md); the frozen encoder that bakes the embeddings is on [molecule-encoder](molecule-encoder.md).

## The two entry points

`conformer_modeller.py::ConformerModeller` extends `train.py::Modeller`. Its `__main__` sets `torch.set_default_dtype(torch.float32)` before the config is read, calls `utils.py::get_train_args`, then `gpu_guard.py::require_free_gpu` (raising `SystemExit` on `gpu_guard.py::GPUBusy`), constructs the modeller and calls `.train()`. The config it takes is a full crystal-route config: `configs/conformer_mk.yaml` carries `project_state_version: 10`, a `protocol`/`protocols` block, `lr_control`, the buffer blocks and an `energy_config` whose `energy_function` is `conformer_torsions`.

`train_conformer.py` is the separate loop. It builds `ConformerTorsions`, `models/gfn.py::GFN` and a TB objective directly (`train_conformer.py::tb_loss`, `train_conformer.py::run`); `train_conformer.py::load_config` defaults to `configs/conformer_dev.yaml`. That file is a different schema from `configs/conformer_mk.yaml`: it has `problem`, `integrator`, `model`, `training` and `eval` blocks, top-level fixed `lr_*` floats and an `adaptive_lr` block, and no `protocol`, `protocols`, `energy_config` or `lr_control` keys. `load_config` passes the parsed config through `utils.py::preflight_config`, which raises `ValueError` on any config carrying a key in `utils.py::_RETIRED_KEYS`. `conformer_dev.yaml` carries two of them at top level, `adaptive_lr` (retired whole at state 10, replaced by `lr_control`) and `lr_warmup_ratio`, so the default config of this entry point does not load at this commit.

## What ConformerModeller inherits and what it overrides

The protocol engine ([stage-protocol-engine](stage-protocol-engine.md)), the learning-rate controller, the batch sizer, checkpointing, OOM handling and the loss composition are inherited unmodified. `ConformerTorsions` implements the same energy protocol `Modeller` calls. `ConformerTorsions.batched_analyze_crystal_batch` and `ConformerTorsions.sample` both raise `NotImplementedError`, the latter naming `brute_force_log_z` and `build_conformer_buffer.py`.

Store classes: `buffer_cls = ConformerBuffer`, `anchor_buffer_cls = ConformerAnchorBuffer`, with `_buffer_kwargs` returning `{}` and `_buffer_y_fn` returning `'conformer_energy'`. State reading: `_batch_latents` returns `energies/conformer_data.py::batch_states`. Energy and model construction: `init_energy_function` filters `energy_config` against `inspect.signature(ConformerTorsions.__init__)`, prints what it drops, and builds either `ConformerTorsions` or `energies/multi_conformer.py::MultiConformerTorsions` depending on how many distinct identifiers `_condition_set_molecules` reads off `cfg:molecules_path`; it also loads `cfg:energy_config.internal_prior_path`, raising `SystemExit` where that prior's `ring_sig_version` is below 2. `_build_gfn_config` adds `angular_mask` from `ConformerTorsions.periodic_dims`, sets `scalar_flow` when the condition set has exactly one member, and pops `_SET_POLICY_KEYS`; `init_gfn` then calls `_install_set_policy`, which refuses a resume (`cfg:checkpoint_name` or `cfg:continue_from_checkpoint`) and a non-zero `dplr_rank`. The eval surface is replaced by `_domain_figs`, `_eval_extra_stats`, `_in_box`, `_reasonable_sample_mask`, `_molecule_features`, `log_physical_properties` and the cached `_e_min`, `_basin_ref` and `_target_coupling`; `_resolve_periodic_centroid_axes` and `_resolve_dead_latent_rows` return `None`. On the anchor and prior paths `_noise_and_condition` jitters `torsion_state` and clips only the non-periodic block, refusing `cfg:buffers.anchor_buffer.tile: shaped`, and `_has_prior_sampler` reports the fitted prior rather than a `prior_model`.

## Stages and losses

`configs/conformer_mk.yaml` sets `cfg:protocol: conformer_unconditional` and defines two stages under `cfg:protocols`. `train_prior` runs `train_mode: bwd` with `bwd_sampling_mode: dataset`, `skip_if: prior_loaded`, flag `update_log_z`, a `hot_lr_sensor` on `bwd/mle`, loss coefficients `bwd: { mle: 1.0, tbc: 0.0, repeats: 1.0 }`, an exit on `gates/progress_done` and `on_exit: ['snapshot:phase1_exit']`. It declares no `snapshot_prior`. `equilibration` runs `train_mode: fused` with `bwd_sampling_mode: prior`, flags `update_log_z` and `buffers_active` with `z_calibration: false`, `on_enter: ['rebuild_prior_by_churn', 'bootstrap_z:rollout:4000']`, entry `fracs: { fwd: 0.0, bwd: 0.9, replay: 0.1 }`, `fwd_rollout_every: 20`, TB on all three branches (`fwd: { tb: 1.0, freeze_policy: 1.0 }`, `bwd` and `replay` at `beta: 80`) and a `gated_ramp` balance between `bwd` and `replay` ([balance-controllers](balance-controllers.md)). It declares no `exit`, so it is terminal. The tier is `cfg:energy_config.level`, which `ConformerTorsions.__init__` takes keyword-only with no default, over `LEVELS = ("torsion", "dihedral", "flex", "full")`; `configs/conformer_mk.yaml` sets `full` with `force_field: mmff`.

## The dataset layer

A conformer condition is a `MolData` (`energies/conformer_data.py::condition_from_energy`) carrying the molecular graph plus a per-atom encoding of the internal-coordinate tree. The field lists are `CTREE_ATOM_FIELDS`, `CTREE_GRAPH_FIELDS` and `STATE_FIELDS`, and every field is per-atom with graph-relative content or per-graph, because `subsample_new_batch` and `append_batch` classify a tensor by `size(0)` alone and neither consults `_slice_dict` nor remaps index values: atom references are deltas from the owning atom (`ctree_ref_a`, `ctree_ref_b`, `ctree_ref_c`, `ctree_closure`) and per-degree-of-freedom values are scattered onto their owning atom, the atom at placement slot `k` owning `min(k, 3)` of them. `ctree_round` is the BFS placement round and equals that rank (`dof_rank`). `ctree_state_col` names the state column driving an atom's torsion; the six `ctree_{r,th,ph}_{col,scale}` fields carry the level-aware reconstruction map, and `ctree_transverse` says that a row's theta/phi pair is held as a transverse pair.

Atoms are stored in placement order, and `pos` is the reference conformer. The sampled quantity is the per-graph `torsion_state`, `[1, k]` deltas on $[-1, 1]$ where 1 corresponds to $\pi$; Cartesian geometry is rebuilt on demand (`states_to_positions`, `batch_tree`). `conformer_energy` is per-graph raw potential at $T = 1$, the `bake_energies` convention, since `ConformerTorsions.prebuilt_sample_to_reward` divides the stored scalar by the sampling temperature itself. `batch_states` and `set_batch_states` are the read and write sides; `attach_states` replicates one condition graph per row and refuses a single row.

File forms: `save_condition_file` writes `{'prior': batch}`, which is what `cfg:molecules_path` is read as; `save_prior_file` writes `{'prior': ..., 'equalized_prior': ...}`, and `init_prior_dataset` reads `equalized_prior` where present. `collate_conditions` raises on mixed `n_torsions`, and `require_conformer_fields` names any missing field. `check_state_convention` builds positions both through the graph and through `ConformerTorsions.build_positions` for random states and asserts they agree within `tol`, making the comparison through a `subsample_new_batch` rather than on the freshly collated batch; `build_conformer_conditions.py` and `build_propanol_benchmark.py` call it.

## Buffers

`buffer.py::ConformerGraphHooks` is a mixin holding the three hooks that touch the crystal data model: `_as_batch` (collate, then `require_conformer_fields`, with no cell or Z' normalisation), `_orient_stored_batch` (a no-op) and `_batch_x` (the stored `torsion_state`, or zeros at `state_dim(batch)` where no state is present). `_compute_xy` is present and defers to the base. `buffer.py::ConformerBuffer(ConformerGraphHooks, CrystalBuffer)` is the churned store for the [prior buffer](prior-buffer.md), the [replay buffer](replay-buffer.md), `mol_dataset` and `prior_dataset`; `buffer.py::ConformerAnchorBuffer(ConformerGraphHooks, AnchorBuffer)` is the [anchor store](anchor-buffer.md), the mixin first in the MRO. Row draws, EMA bookkeeping, admission, purge, TTL and persistence are inherited. `ConformerModeller._prior_row_energy` reads `conformer_energy` off the prior buffer's batch and raises where it is absent.

## The batch cache

`ConformerTorsions._batch(batch_size)` returns a collated tree and force field for that batch size, cached on the device in `_tree_cache` and `_ff_cache`, both keyed on batch size. A hit pops and re-inserts the key, so the dicts order least-recently-used first. A miss builds the tree through `mxtaltools.conformers.builder.collate` and the force field through `_make_ff`, then evicts: the budget is `_batch_cache_slack` (1.5) times the requested batch size, and least-recently-used keys are dropped while more than one entry remains and the summed keys exceed it. The budget is counted in samples, not entries, and the entry just requested is always retained.

## Per-row dispatch, and what is still single-chart

`ConformerTorsions` is one chart: `dof_from_state` multiplies by its own `_M` and reads its own reference vectors. `MultiConformerTorsions(ConformerTorsions)` holds `_members`, one `ConformerTorsions` per identifier, and dispatches per row. `MultiConformerTorsions.energy` groups the batch by `_row_identifiers`, scores each group in its member's chart through `_member_rows`, and regroups; with `n_charts <= 1` or no `mol_batch` it calls the parent unchanged, and a carrier state with no `mol_batch` raises. `MultiConformerTorsions.prebuilt_sample_to_reward` gathers `log_jacobian_const` and `log_chart_jacobian` per row, and where `log_jacobian_const` is `None` (levels `flex` and `full`, where $\prod r^2 \sin\theta$ moves with the sample) recomputes it per member group. Chart-bound methods with no dispatcher form raise, naming the per-member call.

What is not dispatched: `ConformerModeller.log_physical_properties` publishes the in-box and finite-energy fractions, then returns early on a carrier set after printing once that the per-molecule statistics are not computed, so the energy-component, geometry, degree-of-freedom-class, ring and basin-coverage metrics are absent there. `ConformerModeller.sample_from_prior` raises `NotImplementedError` where a non-carrier energy holds more than one distinct SMILES, because that draw goes through the reference member's chart alone.

## Running a leg locally

`ConformerModeller` runs log to the wandb project `GFN Energy`, because `train.py::Modeller.train` passes that string to `wandb.init`; `train_conformer.py` logs to its own `WANDB_PROJECT = "GFN Conformers"`. Both entry points call `require_free_gpu` with no device argument, so a `device: cpu` config is still blocked while another process holds the card; the environment switches and the interpreter are on [dev-traps](dev-traps.md). `cfg:buffer_device` is a separate key from `cfg:device` and defaults to `cuda` in `configs/conformer_mk.yaml`, which also sets `cuda_memory_fraction: 0.75`.

## Could be tooling

Three checks here are static. A schema check would say which of the two entry points a given config can launch, by testing for the keys each requires: `protocol`/`protocols` and `energy_config` for `conformer_modeller.py`, `problem`/`integrator`/`training` for `train_conformer.py`, and would refuse a file carrying both vocabularies. A condition-file inspector would print, for a `molecules_path` or `prior_path` blob, the distinct identifiers, `k` per graph, which `CONFORMER_FIELDS` are present, whether `embedding` and `torsion_state` are there, the dtype of the float tensors against the run's default, and the `check_state_convention` discrepancy re-measured against a freshly built energy. And the dispatch surface is enumerable: a listing of which `ConformerTorsions` methods `MultiConformerTorsions` overrides, which it inherits unchanged, and which raise on a dispatcher, would say from the code alone which quantities are per-row today.
