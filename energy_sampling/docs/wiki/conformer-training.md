The conformer route samples internal-coordinate states of one molecule, or of a set of molecules, against a classical force field. The chart and the free-degree-of-freedom levels are on [conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md); the force field and the fitted `InternalPrior` are on [conformer-force-field-and-prior](conformer-force-field-and-prior.md); the molecule-conditional path, the carrier state and the set policy are on [conformer-conditioning-and-carrier](conformer-conditioning-and-carrier.md); the frozen encoder that bakes the embeddings is on [molecule-encoder](molecule-encoder.md).

## The two entry points

`conformer_modeller.py::ConformerModeller` extends `train.py::Modeller`. Its `__main__` sets `torch.set_default_dtype(torch.float32)` before the config is read, calls `utils.py::get_train_args`, then `gpu_guard.py::require_free_gpu` (raising `SystemExit` on `gpu_guard.py::GPUBusy`), constructs the modeller and calls `.train()`. The config it takes is a full crystal-route config: `configs/conformer_mk.yaml` carries `project_state_version: 10`, a `protocol`/`protocols` block, `lr_control`, the buffer blocks, `energy_function: conformer_torsions` and an `energy_config` of `ConformerTorsions` parameters.

`train_conformer.py` is the separate loop. It builds `ConformerTorsions`, `models/gfn.py::GFN` and a TB objective directly (`train_conformer.py::tb_loss`, `train_conformer.py::run`); `train_conformer.py::load_config` defaults to `configs/conformer_dev.yaml`. That file is a different schema from `configs/conformer_mk.yaml`: it has `problem`, `integrator`, `model`, `training` and `eval` blocks, top-level fixed `lr_*` floats and an `adaptive_lr` block, and no `protocol`, `protocols`, `energy_config` or `lr_control` keys. `load_config` passes the parsed config through `utils.py::preflight_config`, which raises `ValueError` on any config carrying a key in `utils.py::_RETIRED_KEYS`. `conformer_dev.yaml` carries two of them at top level, `adaptive_lr` (retired whole at state 10, replaced by `lr_control`) and `lr_warmup_ratio`, so the default config of this entry point does not load at this commit.

## What ConformerModeller inherits and what it overrides

The protocol engine ([stage-protocol-engine](stage-protocol-engine.md)), the learning-rate controller, the batch sizer, checkpointing, OOM handling and the loss composition are inherited unmodified. `ConformerTorsions` implements the same energy protocol `Modeller` calls. `ConformerTorsions.batched_analyze_crystal_batch` and `ConformerTorsions.sample` both raise `NotImplementedError`, the latter naming `brute_force_log_z` and `build_conformer_buffer.py`.

Store classes: `buffer_cls = ConformerBuffer`, `anchor_buffer_cls = ConformerAnchorBuffer`, with `_buffer_kwargs` returning `{}` and `_buffer_y_fn` returning `'conformer_energy'`. State reading: `_batch_latents` returns `energies/conformer_data.py::batch_states`. Energy and model construction: `init_energy_function` filters `energy_config` against `inspect.signature(ConformerTorsions.__init__)`, prints what it drops, and builds either `ConformerTorsions` or `energies/multi_conformer.py::MultiConformerTorsions` depending on how many distinct identifiers `_condition_set_molecules` reads off `cfg:molecules_path`; it also loads `cfg:energy_config.internal_prior_path`, raising `SystemExit` where that prior's `ring_sig_version` is below 2. `_build_gfn_config` adds `angular_mask` from `ConformerTorsions.periodic_dims`, sets `scalar_flow` when the condition set has exactly one member, and pops `_SET_POLICY_KEYS`. `init_gfn` refuses a non-null `cfg:prior_model_name` (`_refuse_inert_prior_model`) and a compiled set policy (`_refuse_compiled_set_policy`) before the base build or load, then calls `_install_set_policy`, which on a fresh build refuses a non-zero `dplr_rank` and swaps in the set head, and after a checkpoint load checks the stored head against the config instead; `gfn_from_config` is the builder the checkpointer calls on both load paths ([conformer-conditioning-and-carrier](conformer-conditioning-and-carrier.md)). `init_condition_log_z` refuses a tracker whose `library_size` differs from the energy's `condition_library_size`, and on a full resume re-applies `cfg:condition_log_z.{min_visits, half_life_visits, trim_frac, max_batch_weight}` over the restored tracker, printing each value that changes and keeping the checkpoint's `clip_beta`. `scramble_applicable` returns false under the conditional set head. The prior-draw generator `_prior_rng` is created from `cfg:seed` on first use and is stored as `_prior_rng_state` in `checkpointing.py::MODELLER_STATE_DEFAULTS`, so a full resume continues its stream. The eval surface is replaced by `_domain_figs`, `_eval_extra_stats`, `_in_box`, `_reasonable_sample_mask`, `_molecule_features`, `log_physical_properties` and the cached `_e_min`, `_basin_ref` and `_target_coupling`; `_resolve_periodic_centroid_axes` and `_resolve_dead_latent_rows` return `None`. On the anchor and prior paths `_noise_and_condition` jitters `torsion_state` and clips only the non-periodic block, refusing `cfg:buffers.anchor_buffer.tile: shaped`, and `_has_prior_sampler` reports the fitted prior rather than a `prior_model`.

## The dataset layer

A conformer condition is a `MolData` (`energies/conformer_data.py::condition_from_energy`) carrying the molecular graph plus a per-atom encoding of the internal-coordinate tree. The field lists are `CTREE_ATOM_FIELDS`, `CTREE_GRAPH_FIELDS` and `STATE_FIELDS`, and every field is per-atom with graph-relative content or per-graph, because `subsample_new_batch` and `append_batch` classify a tensor by `size(0)` alone and neither consults `_slice_dict` nor remaps index values: atom references are deltas from the owning atom (`ctree_ref_a`, `ctree_ref_b`, `ctree_ref_c`, `ctree_closure`) and per-degree-of-freedom values are scattered onto their owning atom, the atom at placement slot `k` owning `min(k, 3)` of them. `ctree_round` is the BFS placement round and equals that rank (`dof_rank`). `ctree_state_col` names the state column driving an atom's torsion; the six `ctree_{r,th,ph}_{col,scale}` fields carry the level-aware reconstruction map, and `ctree_transverse` says that a row's theta/phi pair is held as a transverse pair. `ctree_stereo_kind`, `ctree_stereo_sign`, `ctree_stereo_nbr` (four atoms as deltas from the key atom) and `ctree_stereo_lo` carry the stereo lock's table on its key atoms ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)), written whatever the energy's `stereo_coeff`; the per-graph `ctree_stereo_coeff` records that coefficient, and `conformer_modeller.py::ConformerModeller._refuse_stereo_mismatch` refuses a `cfg:molecules_path` or `cfg:prior_path` file any of whose graphs records another coefficient than the run's energy.

Atoms are stored in placement order, and `pos` is the reference conformer. The sampled quantity is the per-graph `torsion_state`, `[1, k]` deltas on $[-1, 1]$ where 1 corresponds to $\pi$; Cartesian geometry is rebuilt on demand (`states_to_positions`, `batch_tree`). `conformer_energy` is per-graph raw potential at $T = 1$, the `bake_energies` convention, since `ConformerTorsions.prebuilt_sample_to_reward` divides the stored scalar by the sampling temperature itself. `batch_states` and `set_batch_states` are the read and write sides; `attach_states` replicates one condition graph per row and refuses a single row.

File forms: `save_condition_file` writes `{'prior': batch}`, which is what `cfg:molecules_path` is read as; `save_prior_file` writes `{'prior': ..., 'equalized_prior': ...}`, and `init_prior_dataset` reads `equalized_prior` where present. `collate_conditions` raises on mixed `n_torsions`, and `require_conformer_fields` names any missing field. `check_state_convention` builds positions both through the graph and through `ConformerTorsions.build_positions` for random states and asserts they agree within `tol`, making the comparison through a `subsample_new_batch` rather than on the freshly collated batch; `build_conformer_conditions.py` and `build_propanol_benchmark.py` call it.

## Buffers

`buffer.py::ConformerGraphHooks` is a mixin holding the three hooks that touch the crystal data model: `_as_batch` (collate, then `require_conformer_fields`, with no cell or Z' normalisation), `_orient_stored_batch` (a no-op) and `_batch_x` (the stored `torsion_state`, or zeros at `state_dim(batch)` where no state is present). `_compute_xy` is present and defers to the base. `buffer.py::ConformerBuffer(ConformerGraphHooks, CrystalBuffer)` is the churned store for the [prior buffer](prior-buffer.md), the [replay buffer](replay-buffer.md), `mol_dataset` and `prior_dataset`; `buffer.py::ConformerAnchorBuffer(ConformerGraphHooks, AnchorBuffer)` is the [anchor store](anchor-buffer.md), the mixin first in the MRO. Row draws, EMA bookkeeping, admission, purge, TTL and persistence are inherited. `ConformerModeller._prior_row_energy` reads `conformer_energy` off the prior buffer's batch and raises where it is absent.

## The batch cache

`ConformerTorsions._batch(batch_size)` returns a collated tree and force field for that batch size, cached on the device in `_tree_cache` and `_ff_cache`, both keyed on batch size. A hit pops and re-inserts the key, so the dicts order least-recently-used first. A miss builds the tree through `mxtaltools.conformers.builder.collate` and the force field through `_make_ff`, then evicts: the budget is `_batch_cache_slack` (1.5) times the requested batch size, and least-recently-used keys are dropped while more than one entry remains and the summed keys exceed it. The budget is counted in samples, not entries, and the entry just requested is always retained.

## Per-row dispatch, and what is still single-chart

`ConformerTorsions` is one chart: `dof_from_state` multiplies by its own `_M` and reads its own reference vectors. `MultiConformerTorsions(ConformerTorsions)` holds `_members`, one `ConformerTorsions` per identifier, and dispatches per row. `MultiConformerTorsions.energy` resolves each row to its member through `_resolve_rows` (by `mol_id`, else `identifier`, with pad, `state_mask`, atom-count, placement-order `z` and per-atom `ctree_transverse` checks, a per-graph check of the recorded `ctree_stereo_coeff`, per-atom stereo-lock checks when `stereo_coeff` is above zero, and on a carrier a refusal of a batch without `state_mask`), then scores the whole batch in one pass, `_energy_one_pass`, from its condition graphs and a force field gathered from `energies/ff_library.py::ForceFieldLibrary`, adding each row's own `log_chart_jacobian`; with `n_charts <= 1` or no `mol_batch` it calls the parent unchanged, and a carrier state with no `mol_batch` raises. `MultiConformerTorsions.prebuilt_sample_to_reward` gathers `log_jacobian_const` and `log_chart_jacobian` per row, and where `log_jacobian_const` is `None` (levels `flex` and `full`, where $\prod r^2 \sin\theta$ moves with the sample) recomputes log J from the stored states in one pass over the batch. `member_groups` returns each present molecule's rows. Chart-bound methods with no dispatcher form raise, naming the per-member call.

What is not dispatched: `ConformerModeller.log_physical_properties` publishes the in-box and finite-energy fractions, then returns early on a carrier set after printing once that the per-molecule statistics are not computed, so the energy-component, geometry, degree-of-freedom-class, ring and basin-coverage metrics are absent there. The per-molecule functions of the next section exist, and `ConformerModeller` does not call them. `ConformerModeller.sample_from_prior` raises `NotImplementedError` where a non-carrier energy holds more than one distinct SMILES, because that draw goes through the reference member's chart alone.

## Per-molecule evaluation functions

`energies/conformer_eval_metrics.py` carries pure functions that run the single-chart statistics once per molecule of a set. They take members, member-width states and references as arguments and read nothing off a modeller.

`split_by_member` groups the rows of a set batch by `MultiConformerTorsions._row_identifiers` and returns four dicts keyed by identifier: the member, its member-width rows, their energies and the batch row indices. On a carrier it reads each group back to member width through `CarrierLayout.from_carrier`, and raises `RuntimeError` where a pad column of a row is nonzero or where the batch's `state_mask` differs from `CarrierLayout.valid` for that member. It reads `_row_identifiers`, `_members` and `carrier` and does its own pad and mask checks rather than calling `_resolve_rows`. An energy without `_members`, a plain `ConformerTorsions`, comes back as one group keyed by its SMILES.

`per_molecule_block` returns `{identifier: {key: scalar}}`. A molecule with fewer than `n_min` rows gets only `phys/n_rows`, `phys/k` and `phys/below_n_min` = 1. Every other molecule's row holds the scalar outputs of `energy_component_stats` (called with `hist=False`), `geometry_stats`, `dof_class_stats`, `dof_element_stats`, `ring_stats`, `basin_coverage` and `basin_coupling`, each called on the member with its own rows, and `ring_torsion_stats` reduced to the maximum over the molecule's cycles by `_reduce_ringtor`; with energies it adds `thermal_stats`, and `phys/energy_available` = 0 without them. Arrays and strings are dropped. The block adds:
- `phys/finite_frac`, the fraction of rows with a finite energy;
- `cover/missed_frac`, which is `cover/n_missed` over the accessible basin count;
- `cover/n_modes` and `cover/n_accessible`.

When `nonthermal_entropy_per_dim` $s$ is positive it also adds `thermal/nonthermal_u_star` $= s\,k$, with $k$ the member's `ndim`, and, where energies, a finite $e_{\min}$ and at least one finite energy exist, `thermal/nonthermal_frac` and the scalars of `basin_nonthermal`; otherwise `thermal/nonthermal_available` = 0. `thermal/nonthermal_frac` is the fraction of finite rows whose excess $\max(0, (E - e_{\min})/T)$ exceeds $u^*$, $T$ being the member's `temperature`. `thermal_stats` reads the member's `ndim` as its $d$, so on a carrier $d$ is the molecule's own $k$ and not the carrier width $K$.

The block takes two kinds of reference.
- `refs[identifier]` holds target references. `e_min` is read by `thermal_stats`, `basin_nonthermal` and the non-thermal fraction. `basin_ref`, from `energies/prior_diagnostics.py::basin_reference`, is read by the coverage, coupling and `basin_nonthermal` calls. A missing entry makes those calls publish their `*_available` = 0 flag.
- `reference_x[identifier]` is a population of member-width reference draws. It requires `reference_label`, a token matching `^[a-z][a-z0-9_]*$`, and every key it adds is published under `vs_<label>/`. Those keys are the referenced halves of `dof_class_stats` and `dof_element_stats`; `dof/abs_log_sd_ratio_max`; the ring-torsion ratio, correlation-distance and mean-shift maxima; and `progress_metrics.py::_column_w1_ratio` over the member's own columns and `periodic_dims`, which `per_molecule_w1r` also exposes alone. A molecule missing from `reference_x` gets `vs_<label>/ref_available` = 0.

A population without a label, or a label without a population, raises `ValueError`. With energies given, a member whose `temperature_conditioning` is on raises `ValueError`.

`dof/abs_log_sd_ratio_max` is computed by `_abs_log_sd_ratio_max` as $\max_j |\log(\sigma_j / \sigma^{\text{ref}}_j)|$ over the member's columns whose reference spread is above a floor, with the ratio clipped to $[10^{-6}, 10^{6}]$, so a collapsed column and a widened one score on one scale. $\sigma_j$ is `np.std` on a linear column and `_circ_sd_deg` on a column of `periodic_dims`. A phi state is the displacement from the reference dihedral in units of $\pi$, wrapped to $[-1, 1]$, so a rotamer near 180 degrees from the reference straddles the wrap and its linear standard deviation reads the wrap rather than the width. `dof_class_stats` and `dof_element_stats` take the linear estimator on phi columns, in `dof/phi_sd_ratio_max`, `dof/phi_drift_max` and `dof_elem/phi_<element>_sd_ratio`; the block copies those keys under `vs_<label>/`, and none of them is a headline. `dof_element_stats` groups a column by the element `_central_elements` assigns it, reading the column's driven row through the member's `_M` and `_driven_idx`: a bond's heavier atom, an angle's vertex, a torsion's `torsion_index[:, 1]` atom, and for a transverse column, $u$ or $v$, the vertex of the bend it carries, published under `dof_elem/transverse_<element>_*`; `dof_class_stats` and `geometry_stats` read only the r, theta and phi classes.

`aggregate_per_condition` reduces the rows over `PANEL_HEADLINES`: thirteen entries, five of them population entries, which are included only when a label is passed and are then published under `vs_<label>/`. Each entry maps a per-molecule key to a badness through the transform `identity`, `abs_dev` ($|v - \text{ideal}|$) or `shortfall` ($\text{ideal} - v$).
- For each headline it publishes `<ns>/<name>/n` and `<ns>/<name>/n_unavailable`. Where at least one molecule carries a finite value it also publishes `/median`, `/max` and `/worst`. `/worst` is the $1 - q$ quantile for `worst_quantile` $q$, the tail convention `utils.py::per_condition_fraction` uses with `higher_is_worse`.
- It also publishes `<ns>/n_molecules` and `<ns>/n_below_n_min`.
- A scored molecule with no finite value for a headline counts in `n_unavailable` and enters no statistic of it. A molecule below `n_min` enters no headline.
- The key count is at most $2 + 5 \times 13$ whatever the number of molecules.
- The `thermal/T_eff_over_T_dev` headline takes ideal 2.0, the reading of `thermal_stats` on an excess of $d/2$ (see [conformer-force-field-and-prior](conformer-force-field-and-prior.md) for the three zeros).

`aggregate_per_condition`, `worst_molecules` and `per_molecule_correlations` call `_check_row_labels` first. It raises `ValueError` when a row carries a `vs_<label>/` key under any label other than the one passed, including when none is passed.

`worst_molecules` returns the `k` largest badness values on one headline with their identifiers. `molecule_features` returns `k`, `n_rings` from `energies/ring_metrics.py::ring_cycles`, `n_rotors`, and the `n_modes` it is given. `n_rotors` is counted by `_n_rotors`: the groups of `ConformerTorsions.torsion_groups` whose central bond is, in the member's RDKit molecule, a single bond in no ring, and it raises where a central bond is not a bond of that molecule. Methyl, hydroxyl and amide C-N groups count; ring, aromatic and double bonds do not. `per_molecule_correlations` passes the per-molecule badness of each headline in `CORR_HEADLINES`, with those four features, to `feature_correlations`, which publishes `*_available` = 0 for a feature with fewer than `min_groups` (default 3) distinct values.

`select_panel` sorts the identifiers and returns all of them when there are at most `size`. Otherwise:
- It stratifies by equal-count bins of `k` over the candidates (`n_k_bins`, default 3), by ring ($n_{\text{rings}} > 0$) and by basin availability ($n_{\text{modes}} \ge 2$).
- When `size` is at least the number of non-empty strata, each stratum gets one slot. The rest is allocated largest-remainder in proportion to each stratum's remaining size, in integer arithmetic.
- Each stratum's members are drawn by permutations of one `numpy.random.default_rng(seed)` generator, taken in sorted stratum order, and the result is returned sorted.
- It raises on a duplicate identifier, a `size` below 1, and a candidate with no features.

## The offline reference table

`build_conformer_references.py` computes, once per distinct identifier of a conditions file, the target references that `per_molecule_block` takes as `refs`, and writes them to one file keyed by identifier. `ConformerModeller` does not read it: `ConformerModeller._e_min` still runs `tier_minimum` lazily on `self.energy_function` from 256 rows drawn by `torch.randperm` over `prior_dataset.x`, and `_basin_ref` still calls `basin_reference` on that same energy.

*Input and members.* `read_conditions` reads the `prior` batch of a `cfg:molecules_path`-form file and returns, per distinct identifier, its SMILES, placement-order `z` and reference `pos`; an identifier carrying two different SMILES raises `ValueError`. The member arguments are the run's `energy_config` passed through `member_kwargs`, the same signature filter `init_energy_function` applies, without `smiles`; the command line reads them from `--config` through `utils.py::preflight_config` and `resolve_derived_config`. `build_member` constructs `ConformerTorsions(smiles=..., device='cpu', dtype=torch.float64, **kw)`, and `check_member_matches` raises where the member's `spec.z` differs from the file's `z` or its `ref_pos` from the file's `pos` by more than `REF_POS_TOL`, $10^{-5}$ Å.

*The stereo pin.* `condition_stereo` parses the condition's SMILES as `AddHs(MolFromSmiles(smiles))`, the construction `ConformerTorsions.__init__` uses for `ConformerTorsions.mol`, and raises `ValueError` when the parse's atoms and bonds do not carry the same indices as the member's mol. The pinned elements are the atoms with a tetrahedral tag and the double bonds with an E/Z label in that parse. Their target is the configuration RDKit's `AssignStereochemistryFrom3D` perceives on the reference state, whose positions `rdkit_positions` returns in RDKit atom order. Where that configuration differs from the SMILES's at a pinned element, `condition_stereo` raises `ValueError`; this includes a tagged tetrahedral N, for which 3D perception returns no configuration. With RDKit set to non-legacy stereo perception (`Chem.GetUseLegacyStereoPerception` false) it raises `RuntimeError`. Each entry records:
- `stereo_pin`: `none` when the SMILES tags nothing, `full` when every element perceived on the reference is tagged, and `partial` otherwise;
- `stereo_pinned`: the pinned atoms and bonds;
- `stereo_open`: the perceived elements the SMILES leaves untagged, with a count of those that are =NH imine double bonds, that is, bonds with an N end whose only other neighbour is H. An implicit-H SMILES cannot tag such a bond;
- `stereo`: the reference's isomeric SMILES from `stereo_signatures`, which is `MolToSmiles(RemoveHs(...))` of the perceived mol.

*The floor.* `search_starts` assembles four kinds of start:
- the reference, state 0;
- `etkdg_starts`: the molecule re-embedded by `_embed` at ETKDG seeds `seed+1` to `seed+n_seeds`. The template is the parse from `condition_stereo`, which carries the SMILES's stereo tags and no others. Each embedding is MMFF-optimised when `mmff_reference` is on, then measured in the member's own tree by `_state_of_positions` (`mxtaltools/conformers/builder.py::measure`, then `ConformerTorsions.state_from_dof`). An embedding whose configuration differs from the target at a pinned element is dropped and counted. Each embedding carries `ETKDG_TIMEOUT_S` (10 s), and after `ETKDG_MAX_FAILURES` (3) failed embeddings the remaining seeds are skipped. The seeds of the returned starts are kept as `etkdg_seeds`. A collective level raises here, since `state_from_dof` has no row-wise inverse there;
- `n_uniform` draws of `prior_baselines.py::draw_uniform`;
- `n_prior` draws of `prior_baselines.py::draw_prior`. A draw that raises is replaced by as many uniform draws, and its message is kept as `prior_error`.

The draws are seeded from `molecule_seed`, a blake2b hash of the identifier, and every start is clamped into $[-1,1]$. `floor_search` runs `prior_baselines.py::descend` from all starts, re-scores every candidate with `bake_energies`, and walks the candidates in increasing energy until one whose `stereo_labels` equal the target, or takes the first when nothing is pinned. That candidate gives `e_min`, `e_min_state` and `e_min_stereo`, the candidate's isomeric SMILES. For a stereo-free SMILES, then, `e_min` is the lowest candidate of any stereoisomer. `e_min_unpinned` is the lowest candidate of any stereochemistry, and `n_below_other_stereo` the number of candidates below `e_min`, each of which differs from the target at a pinned element. `e_min` is raw potential at $T = 1$ in kcal/mol, the `bake_energies` currency of `conformer_energy`, and not the tracker's `best_energy`, which is $-T\log r$.

*Basins.* `basin_block` stores `basin_reference` at `max_modes` 512 as `basin_ref`, `energies/conformer_eval_metrics.py::target_coupling` of it as `target_tc`, `n_modes` (counted from `energies/prior_diagnostics.py::rotamer_modes` when the enumeration is skipped), `n_accessible` (None when skipped) and `basin_skipped`.

*The entry* also holds `k`, `n_atoms`, `n_rings` (from `ring_cycles`), `u_ref` (the reference state through `bake_energies`), `worst_start`, `n_starts`, `n_nonfinite`, `e_min_start_kind`, the per-kind start counts, the seed and the per-phase wall times `cost_s`.

*The stamp* records:
- `format`, `conformer_references/2` (a `/1` table pinned every element perceived on the reference);
- the conditions file's path, sha256, identifier count and sorted identifiers;
- `energy`, from `defining_energy`: every parameter of `ConformerTorsions.__init__` except those in `NON_DEFINING_KWARGS` (device, dtype, the condition-vector switches, `log_temperature_range` and the four ring-sampler arguments), with each one the caller omitted filled from the signature default;
- `level`, `force_field`, `energy_clip` and the raw arguments;
- the search and basin parameters, and the internal prior's path and sha256 (None when `n_prior` is 0);
- the currency string, and `code_revisions`: the gfn and mxtaltools commits with a dirty flag, and the rdkit, torch and numpy versions.

*Loading.* `load_references(path, conditions_path=..., energy_kwargs=..., require_complete=True)` requires the first two keyword arguments. It raises `StaleReferencesError` when the file's format differs, when the conditions file's sha256 differs from the stamp's, or when any member-defining argument, resolved the same way, differs; code revisions are not compared. When an identifier of the stamp has no entry it raises `IncompleteReferencesError`, a subclass, naming the first missing identifier and its recorded failure; with `require_complete=False` it loads the table with those identifiers in `ReferenceTable.missing`. It returns a `ReferenceTable`:
- `ReferenceTable.verify(members, tol, allow_missing=False)` re-scores each `e_min_state` through the given members with `bake_energies`. It raises `StaleReferencesError` where a gap exceeds `EMIN_RESCORE_TOL` ($10^{-2}$ kcal/mol), where a member's `ndim` differs from the entry's `k`, or where a member has no entry, which `allow_missing` skips instead;
- `ReferenceTable.eval_refs` returns `{identifier: {e_min, basin_ref, target_tc}}`, the `refs` form of `per_molecule_block`, leaving out identifiers without an entry;
- `ReferenceTable.column` returns one field in a given identifier order, raising `KeyError` on an identifier without an entry and `ValueError` where the field is None, as `n_accessible` is on a skipped basin enumeration;
- `ReferenceTable.prior_fallbacks` lists the identifiers whose entry carries `prior_error`; `build_references` returns the same list and `main` prints its length.

*Resume and bounds.* Each finished entry is written at once to `<out>.parts/`, under a key hashed from the format, the conditions and prior sha256 values, `energy`, and the search and basin parameters. A rerun skips identifiers with a part under the same key, and raises `ValueError` when the directory holds a part under another key. The table is written through a temporary file and `os.replace`, with failed molecules under `failures`; the parts directory is removed once a build covers every identifier with no failure. With `workers` above 0 the molecules run in a spawn pool, and `build_references` waits on it for at most `--molecule-timeout` seconds (default 900) per completion. When that window passes with no molecule finished it terminates the pool, records every unfinished molecule as a failure and writes the table; `main` then returns 3, and 1 for failures without a stall.

*Search depth and cost.* `DEFAULT_SEARCH` is 32 ETKDG seeds, 127 uniform and 128 prior draws, and 150 steps, 288 starts with the reference. The depth census behind it, with its scripts and outputs, is in `artifacts/conformer_references_2026-09-26/` (`calib_depth.py`, `analyze_depth.py`, `mirror_pairs.py`).
- **[calibration, depth census, 2026-09-26]** At `DEFAULT_SEARCH`, `e_min` exceeds the lowest pin-keeping candidate of a pool of about 2,100 starts per condition by at most 0.11 kcal/mol on 98 stereo-free QM9 conditions and by at most 0.30 kcal/mol on 89 tagged ones; level `full`, `mmff`, `energy_clip` 300.
- **[calibration, 20-molecule build, 2026-09-26]** 20 random census members, $k$ 39 to 66, 4 workers of one thread at `DEFAULT_SEARCH`: per-molecule wall time p50 5.3 s, maximum 8.4 s, of which the descent is p50 4.8 s.

## Per-condition log Z check

`eval/conformer_logz_check.py` is an offline program, run as `python -m eval.conformer_logz_check --config <run config> [--checkpoint <file>]`. Per condition it reports an importance-sampling estimate of $\log Z(c)$, an exact value by quadrature where the molecule has at most `--max-quad-dim` (default 6) free coordinates, the tracker's values and the learned head, as captioned tables whose captions carry the level, $N$, the seed and the checkpoint step.

*Model and data.* `build_modeller` loads the run's config through `utils.py::preflight_config` and `resolve_derived_config` with `cfg:checkpoint_read_only` true and the command-line device. Given a checkpoint it sets `cfg:checkpoint_name` to it, suffixes the run name with `_logz_check` and sets `cfg:buffers.fresh_on_switch`, so `checkpointing.py::Checkpointer.load_full` restores the model, the EMA, the P_B snapshot and the tracker and does not read the buffer sidecar. `init_modeller` refuses `cfg:temperature_conditioning`, then runs `init_energy_function`, `init_gfn`, `init_mol_dataset`, `init_prior_dataset` and `init_identifiers` in the order `train.py::Modeller.train` does, so condition ids come from the same identifier registry; `init_gfn` is skipped under `--proposal prior` when no checkpoint is named.

*The card.* `main` calls `gpu_preflight` before the modeller is built. `train.py::Modeller.__init__` opens a CUDA context on GPU 0 whenever `torch.cuda.is_available()`, whatever the configured device, so for a device that is not `cuda` `gpu_preflight` first sets `CUDA_VISIBLE_DEVICES=-1`. If CUDA still reports a device, the runtime was initialised in this process before the variable was set; the variable is then restored. `gpu_guard.py::require_free_gpu` then runs for every device, with the run's config: it skips itself when no GPU is visible and otherwise judges the card as for any launch ([compute-guards](compute-guards.md)).

*Importance sampling.* With `--proposal policy` (the default) `policy_rollouts` draws `--n` (default 10000) forward rollouts of `ema_model` per condition from that condition's row of `mol_dataset`, or of the held-out set, through `eval/utils.py::sample_eval_fwd_trajs`, seeded from `--seed` and the identifier. The rollouts take `cfg:integrator.T` steps (`utils.py::get_discretizer`), where the eval's pooled log Z takes `cfg:eval_T`; the result records both and the report notes a difference. `is_summary` returns $\log\hat Z = \log\frac1k\sum_i w_i$ with $\log w = \log R + \log P_B - \log P_F$, the Kish ESS, the delta-method standard error $\mathrm{SE}^2 = 1/\mathrm{ESS} - 1/k$, and the sample mean of $\log w$, where the sums and $k$ run over the finite $\log w$; non-finite ones are left out and counted, and ESS/N is over all $N$. With `--proposal prior`, `prior_estimate` calls `energies/prior_diagnostics.py::is_log_z` on the member with the fitted `InternalPrior`; that function scores at $T = 1$, so the prior proposal is refused at any other temperature, and it raises `NotImplementedError` on ring blocks, where the row carries no estimate. `is_log_z` subtracts the prior's log density over every coordinate `ConformerTorsions.sample_prior_states` draws, while the state at a level other than `full` holds only that level's free coordinates, so the prior proposal is also refused at any level other than `full`.

*Quadrature.* `grid_log_z` is the left-endpoint rule of `ConformerTorsions.brute_force_log_z` with one node count per block (r, theta, phi) and an optional shift of every node by a fraction of a cell. Phi axes cover one period; the other axes cover the box, or extend past it by whole cells to `--quad-lin-half`. At an isotropic unshifted grid it returns `brute_force_log_z`'s value. `two_grid_log_z` evaluates two grids, by default `16,8,32` and the same grid shifted by half a cell, refuses a pair in which some block of the member keeps the same nodes, and marks the pair converged when the two values differ by at most `--quad-tol` (default 0.02 nats); the first grid's value is the one reported. `integrand_identity` scores 256 uniform box states through the member's `-energy` and through the run energy's `log_reward` on the carrier-placed rows of that condition's batch, and `check_integrand` refuses when they differ by more than $10^{-4}$ relative. A member with transverse columns gets no quadrature. For every condition that will be integrated, `run_check` makes the unrefined-pair refusal, the refusal of a grid over `--quad-max-points` nodes (`refuse_over_budget`) and the integrand refusal before any rollout.

*Verdicts.* `_is_problem` judges every row's estimate, returning the first that applies of `NOT_RUN` (no estimate), `NONFINITE_ROWS`, `INVALID_PROPOSAL` (a prior clip fraction above $10^{-3}$) and `BELOW_ESS_FLOOR` (ESS under `--min-ess`, default 100, or ESS/N under `--min-ess-frac`, default $10^{-3}$); the row's `is_status` is that value or `ok`. A row with an exact value takes `exact_verdict`: the floor's value when there is one, then `UNCONVERGED`, otherwise `PASS` when $|\log\hat Z - \log Z_A| \le \max(k\,\mathrm{SE} + |\log Z_A - \log Z_B|,\ \epsilon)$, with $k$ = `--k-se` (default 3) and $\epsilon$ = `--abs-tol` (default 0), and `FAIL` when not. A row without one takes the floor's value, or `ESTIMATE_ONLY` when the estimate clears the floors. Table 1 prints the count of non-finite $\log w$; Table 2 prints `is_status` and leaves the head and tracker gaps blank on a row that is not `ok`. `--pair A B` names two conditions that must share $\log Z$; `pair_verdict` compares their estimates against $k\sqrt{\mathrm{SE}_a^2 + \mathrm{SE}_b^2}$ under the same floors, on both rows. The exit status (`exit_status`) is 1 when any row or pair verdict is other than `PASS` and `ESTIMATE_ONLY`; otherwise it is 0 when some verdict is `PASS` and 3 when none is, which the report's last line states as nothing checked. It is 2 when `main` catches `Refused` or argparse rejects an argument. `Refused` covers `cfg:temperature_conditioning`, a busy card, an unknown condition, the grid refusals, the integrand refusal, a tracker sized for other conditions and the prior proposal's preconditions ($T = 1$, level `full`, a fitted prior). An uncaught error exits 1 with its traceback.

*The prior proposal's coverage.* `ConformerTorsions.sample_prior_states` and `.prior_log_prob`, which scores its draws, both called by `is_log_z` with the default `joint_torsions=True`, hold two kinds of acyclic phi row about the reference: each improper row (`.improper_phi_rows`) about its reference value at `.improper_phi_sigma`, and each non-leader row of a sibling group (`.torsion_groups`) at its reference offset from the group's leader, at the group's `.sibling_jitter_sigma`. With the stereo lock on they also hold the rows `.held_phi_rows` adds about a locked double bond, at `.improper_phi_sigma`; `energies/invertible_centres.py::centre_table` reads `.improper_phi_rows` and the sibling groups only, so it does not read those rows. Negating every phi, the global reflection ([conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md)), takes a held value $v$ to $-v$. The table's centres are atoms, named by placement slot, that place held rows and whose flip of those rows is an exact inversion by structure ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)); an entry is marked `planar` when $|\mathrm{wrap}(2v)|$ is at most `MIRROR_WIDTHS` (1.0) times the row's width on every row its flip moves ($v$ an improper row's reference value, or a substituent's reference offset from its group's pivot or ring frame), since a row whose reference value is 0 or $\pi$, as at a planar centre, is its own reflection. The level-`full` target holds configurations of both parities at each non-planar centre the lock leaves free, and without the lock these include the reflection of every conformer at equal energy. `.sample_prior_states` flips each centre of `energies/invertible_centres.py::invertible_centres` (free, and three-coordinate, planar or not) on each draw with probability 1/2, independently per centre, and `.prior_log_prob` scores that mixture ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)). `prior_held_parity_centres` returns the table's other centres that are not planar: the `LOCKED` ones, the four-coordinate ones, and the `UNKNOWN` ones, whose lock table cannot be read; an estimate from the prior omits the target's mass on the unproposed side of a free one. `prior_coverage_bias` returns a reason naming those centres, each with a note of why the prior does not flip it (its coordination, or `lock state unread`), or `None` when there are none; a centre without an entry in the table is not named. When the member's `stereo_coeff` is above zero it first removes the centres whose table entry is `LOCKED`, those a tetrahedral element of the member's lock table (`stereo.kind`, `stereo.key`) is keyed on, and it removes none when that table cannot be read. Under `--proposal prior` `run_check` stores that reason on every row with an estimate, adds it to the row's notes, and sets `is_status` to `KNOWN_BIASED` on a row the floors pass. A row without an exact value then takes the verdict `KNOWN_BIASED` in place of `ESTIMATE_ONLY`; a row with one keeps `exact_verdict`'s. `pair_verdict` returns `KNOWN_BIASED` for a pair that clears the floors when either row carries the reason, and still reports the delta. With `--proposal policy` no row carries it.

*Tracker and head.* `tracker_reading` reads `ema_logw`, `ema_log_z_emp` and `count` at the condition id from the checkpoint's `condition_log_z`, with `trusted` the mask `buffer.py::ConditionLogZTracker.lookup` applies. A tracker whose `library_size` differs from the energy's `condition_library_size` is refused. The head is the mean of `log_flow[:, 0]` over the condition's rollouts. The report prints both beside the estimate and labels neither as a validated $\log Z$; which of them bounds $\log Z$ depends on the tracker's feed ([on-policy-and-off-policy-training](on-policy-and-off-policy-training.md)).

*Partition identity.* `partition_identity` computes the unlocked $\log Z$ and $\log\sum_s Z(s)$ over the $2^n$ sign assignments of a caller's energy builder, every term on one grid. `--partition-identity` is refused with exit status 2 before anything is read. `stereo_seam_missing` lists the keywords of `STEREO_SEAM` that `ConformerTorsions.__init__` does not take, and the refusal names them when it lists any; `ConformerTorsions.__init__` takes `stereo_coeff`, the one entry, so the refusal states instead that no sign override is wired from the lock to `partition_identity`.

## Offline per-condition model evaluation

`eval/conformer_model_eval.py` is an offline program, run as `python -m eval.conformer_model_eval --config <run config> --checkpoint <file>`. From `--n-per-condition` (default 2048) forward draws per condition and from references that do not depend on the sampler, it reports three families per condition (quality, coverage, and the trajectory-balance log-weights with $\log Z(c)$), judges each condition against bars given as options, prints Tables 1a to 7 with captions, and with `--out` writes `report.txt` and `eval.json`. It runs no Markov chain and computes no basin population.

*Model and data.* `build_eval_modeller` calls `conformer_logz_check.py::build_modeller`, so the config is read with `cfg:checkpoint_read_only` true and without the buffer sidecar, and replaces that instance's `checkpointing.py::Checkpointer._gfn_config_from` by a wrapper that sets the returned `gfn_config['device']` to `--device` before `ConformerModeller.gfn_from_config` builds the model; `models/gfn.py::GFN` places tensors on that device during construction. `tests/conformer/test_conformer_model_eval.py::test_the_loader_reads_the_checkpoint_and_builds_a_cuda_stamped_one_on_the_cpu` builds a checkpoint stamped `cuda` on the CPU through it and, where no GPU is visible, shows `conformer_logz_check.py::init_modeller` raising `RuntimeError` on the same file. `init_eval_modeller` refuses a `cfg:energy_function` other than `conformer_torsions`, runs `init_modeller`, and turns its `SystemExit` (`ConformerModeller._refuse_stereo_mismatch`) and its `ValueError` or `NotImplementedError` (`Checkpointer.assert_problem_match`, `ConformerModeller._assert_checkpoint_layout`, `ConformerModeller._assert_condition_set`, `ConformerModeller._check_reloaded_policy`) into `Refused`, exit status 2. It then refuses a named checkpoint without a tracker and a tracker whose `library_size` differs from the energy's `condition_library_size`. Before `init_modeller` runs, `_small_prior_draw` replaces that instance's `init_prior_dataset` by a wrapper that, for a carrier energy without `cfg:prior_path`, sets `cfg:energy_config.prior_sample_size` to 1 for the call and restores it afterwards. `ConformerModeller._draw_carrier_prior` draws $\max(\lceil n/\text{members}\rceil, 2)$ rows per member, so every member still draws and `init_identifiers` builds the same registry; `tests/conformer/test_conformer_model_eval.py::test_the_loader_reads_the_checkpoint_and_builds_a_cuda_stamped_one_on_the_cpu` compares the registry and `condition_library_size` with those `init_modeller` gives on the same checkpoint at the config's size. `identity_exempt` returns the keys of `utils.py::_NON_IDENTITY_ENERGY_CONFIG_KEYS` that are `ConformerTorsions.__init__` parameters, with the config's value or the signature default: `bounding_coeff`, `lj_coeff` and `energy_clip`. The checkpoint's problem identity leaves them out and the checkpoint stores no value for them, so a config that sets any of them differently from the training run loads without refusal; the report prints the three values. A checkpoint whose `gfn_config['conformer']` carries `condition_set` is refused when the conditions file names other identifiers or members (`ConformerModeller._assert_condition_set`); from one written before that stamp, two condition files of one layout and one condition count naming different molecules load alike. The report prints the conditions file's sha256.

*The draws.* `rollout_condition` makes the three calls of `eval/utils.py::sample_eval_fwd_trajs` (`condition_samples`, `get_traj_fwd` on `ema_model`, `log_reward` with `return_exp`) on `cfg:eval_T` uniform steps, seeded per condition by `conformer_logz_check.py::_seed_for`, timing the rollout and the reward apart. Per row it keeps the terminal state, $\log R$, the summed $\log P_F$ and $\log P_B$, `log_flow[:, 0]` and the baked `conformer_energy`. At equal steps, seed and batch its $\log w$ equals `policy_rollouts`' within $10^{-4}$, the float32 rounding of that function's sum (`tests/conformer/test_conformer_model_eval.py::test_the_eval_rollouts_are_the_logz_checks`). $P_B$ is the snapshot `load_full` restored when the checkpoint holds one, and the Table 3a caption says which. `ema_model` holds the checkpoint's `model_eval`; with `cfg:ema_decay` null, `train.py::Modeller.update_ema_model` sets `ema_model` to `gfn_model`, so `model_eval` holds the training weights, and the captions state `cfg:ema_decay`. `evaluate` reads each condition's rows back to member width through `split_by_member` and calls `per_molecule_block` once, with `N_MIN` (32) as `n_min`, the reference table's `eval_refs` and `cfg:nonthermal_entropy_per_dim`.

*Quality.* From the block's row: the finite fraction, `geom/all_in_range` (the in-box fraction), `E/clip_active_frac`, `thermal_stats`' $T_{\text{eff}}/T = 1 + 2\,\mathrm{median(excess)}/k$ and the non-thermal fraction. Added per condition:
- `stereo_lock_stats`: from `build_positions` and the member's `StereoTable`, the fraction of rows whose `lock_energy` is above 0 and the fraction with some element at $s\,v < 0$; `na` when `stereo_coeff` is 0 or the table has no element;
- `clash_stats`: `energies/prior_smoke.py::_worst_overlap` per row, the largest $\mathrm{relu}(\sigma - r)/\sigma$ over the force field's nonbonded pairs, which at `min_separation` 3 include the 1-4 pairs; the fraction above `Bars.clash_overlap` (default 0.5), its p50, p99 and maximum, and its value at state 0; `na` with no pair. For MMFF, $\sigma = 2^{-1/6}R^*$ (`mxtaltools/conformers/energy.py::CONTACT_SIGMA_SCALE`);
- `excess_stats`: $(E - e_{\min})/T$ in kT over finite rows, $E$ the baked energy, with p10, p50, p90, p99, the maximum and the rows more than `EMIN_RESCORE_TOL` below $e_{\min}$.

**[calibration, `buffered_147` over the MMFF pairs of CO, CC, CCO, CCCC, phenol and N-methylacetamide, 2026-09-27]** At $r = 0.75\sigma$ the pair term is 57 $\epsilon$, 1.1 to 3.9 kcal/mol; at $r = 0.5\sigma$ it is 1174 $\epsilon$, 22 to 80 kcal/mol; $\epsilon$ spans 0.019 to 0.068 kcal/mol.

*References.* `load_or_build_references` loads `--refs` through `load_references` with `require_complete=False`. Without `--refs` it reads `references.eval.pt` in the cache directory (`--cache-dir`, default `<out>/cache`) with `require_complete=False`, and uses it when `load_references` accepts it, its stamp's search equals `EVAL_SEARCH`, and it holds an entry or a recorded failure for every condition asked for. Otherwise it builds it there with `build_references` at `EVAL_SEARCH` (8 ETKDG seeds, 55 uniform starts, no prior starts and 150 steps, 64 starts with the reference), passing the `--conditions` identifiers that are in `cfg:molecules_path` as `identifiers`, so a subset evaluation builds entries for that subset only; `build_references` resumes from the per-molecule parts it keeps beside a table that does not cover the whole file. `ReferenceTable.verify` re-scores the floor state of every entry asked for through the run's member, and a `StaleReferencesError` becomes `Refused`.

*Coverage.* `coverage_block` reads the block's `cover/` keys against the entry's `basin_ref`: accessible basins (`energies/prior_diagnostics.py::basin_reference`, mode energy with every other coordinate at the reference geometry within 10 kT of the lowest), missed and visited counts, the least-visited accessible basin's share times the accessible count (1 at uniform visitation), the normalised occupancy entropy, the debiased total correlation and suppressed combinations of `basin_coupling` beside the entry's `target_tc`, and `basin_nonthermal`. No reference entry sets `why`, and the coverage bar is then `UNAVAILABLE`. Where the entry's `basin_ref` records a skipped enumeration (more product basins than its `max_modes`), `coverage_block` returns `marginal_coverage` of the condition's draws, of kind `marginal`: the groups and centres of `energies/prior_diagnostics.py::rotamer_modes`, each draw labelled per group by `energies/prior_diagnostics.py::rotamer_group_labels`, a centre missed when no draw carries its label. `rotamer_modes` keeps a centre only where the scan density exceeds 0.05 of the group's maximum, so every centre lies within $\ln 20 \approx 3$ kT of its group's best in the 1-D scan. The coverage bar then reads that count, and its bar text says `marginal`. A missed centre implies every product basin through it is missed, so the marginal count is a lower bound on missed basins. A skipped enumeration without draws sets `why` naming the skip, which the bar reads as `UNAVAILABLE`. The rotamer basins do not separate the two sides of a non-planar centre. `parity_coverage` takes the centres of `energies/invertible_centres.py::free_centres`: the entries of the table the prior's flip reads ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)) that are not marked `planar`, without the centres the member's lock table names (those a tetrahedral element of it is keyed on) when `stereo_coeff` is above zero; and per remaining centre it reports its `kind` and `n_bonded`, the share of draws on the reference side (`energies/invertible_centres.py::reference_side` on the draws' built positions: the sign of the triple product of three of the centre's neighbours about it), and `missed` when every draw sits on one side. Every centre counts, so `n_accessible` equals `n_centres`, and no energy enters. At a collective level the table is empty and `parity_coverage` returns an `na` naming the level. Rows written before 2026-09-28 are not comparable with later ones on ring molecules, at crowded centres and, under the lock, at the atom a double-bond element of the lock is keyed on: the table's rule changed that day, and a checkpoint that passed the parity bar before that date can fail it after on the same draws. The lock names every atom with four bonded neighbours (`energies/stereo_lock.py`), so with it on a free centre has fewer, as an amine N has. No quantity here is a basin population or a Boltzmann weight.

*Log-weights and log Z.* `logw_block` returns `is_summary`'s values plus the population standard deviation of the finite $\log w$, `kl_gap` $= \log\hat Z - \overline{\log w}$, and `bootstrap_log_z_se` over `--n-boot` (default 200) resamples, which becomes `se`, the delta-method value kept as `se_delta`. `pareto_khat` sorts the finite $\log w$, scales the weights by the largest and fits `gpd_fit` to the $M = \lceil\min(0.2N, 3\sqrt N)\rceil$ largest as exceedances over the $(M{+}1)$-th. `gpd_fit` is the Zhang and Stephens posterior-mean estimate over $30 + \lfloor\sqrt n\rfloor$ grid points followed by $(nk + 5)/(n + 10)$, the computation of arviz's `_gpdfit`. The test file pins its values on three sets of generalised-Pareto quantiles to those of pyro-ppl 1.9.1's `fit_generalized_pareto` within $10^{-10}$, and compares `pareto_khat` with that function live where pyro is installed. pyro is not a dependency of this repository. `pareto_khat` returns $-\infty$ when every $\log w$ is equal, and NaN with fewer than 10 finite weights or fewer than 5 positive exceedances. The tracker is read by `tracker_reading`. For each condition with $k \le$ `--quadrature-max-d` (default 6) `evaluate` runs `check_integrand` and the grid refusals before any rollout, then `cached_quadrature`: `two_grid_log_z` memoised in `quadrature.json` in the cache directory, keyed by the conditions file's sha256, the identifier, `defining_energy`, $T$ and the grid arguments. `is_status` gives every row `_is_problem`'s value under `Bars.floors`, else `PARETO_K_ABOVE_BAR` when k-hat is at or above `Bars.max_pareto_k`, else `ok`; it applies to rows without an exact value. Tables 3a to 3c print it, and on a row that is not `ok` `_gap` blanks `kl_gap`, the two tracker gaps and the head gap, and leaves the row out of the two IS gap rows of the median-and-worst table. The IS $\log Z$ itself is printed on every row. `stereo_pairs` groups conditions by `build_conformer_set.py::constitution_key` and names a pair `same isomer` or `mirror` by comparing `build_conformer_conditions.py::smiles_identity` of one against the other and against `models/encoder_probe.py::mirror_smiles` of it, else `diastereomer`; every pair gets `pair_verdict`, whose verdict becomes `PARETO_K_ABOVE_BAR` when it is `PASS` or `FAIL` and either row has that status, and the kinds in `MUST_AGREE` enter the exit status. No row carries `KNOWN_BIASED`, whose rule reads the prior proposal only.

*Bars and exit status.* `judge` gives each of nine bars `PASS`, `FAIL`, `n/a` or `UNAVAILABLE` from `Bars`. The defaults are:
- finite fraction $\ge 1$, in-box $\ge 0.99$, lock-active $< 10^{-3}$, clash $\le 10^{-3}$ at overlap 0.5;
- missed basins $\le 0$ (joint, or marginal as above), missed free centres $\le 0$;
- `ess_floor`, which fails when `_is_problem` returns a value (ESS under `min_ess` 100, ESS/N under `min_ess_frac` $10^{-3}$, a non-finite $\log w$, or no finite estimate), with or without an exact value;
- Pareto $k < 0.7$;
- the exact check, which `judge` takes from `exact_verdict` at $k_{SE} = 3$ and `abs_tol` 0.1 nats, and which fails on any verdict other than `PASS`.

The verdict-table caption labels them working assumptions. `overall` fails a condition on any `FAIL` or `UNAVAILABLE`. `exit_status` is 1 when some condition fails or some `MUST_AGREE` pair's verdict is not `PASS`, else 0; `main` returns 2 on `Refused`, and refuses an identifier outside the run's condition rows before the references are read. `_median_worst` names the condition at the worst value, or `all tied` or `tie` with the tied conditions when more than one condition has it. `Cost` accumulates wall seconds per phase for Table 7.

## Could be tooling

Three checks here are static. A schema check would say which of the two entry points a given config can launch, by testing for the keys each requires: `protocol`/`protocols` and `energy_config` for `conformer_modeller.py`, `problem`/`integrator`/`training` for `train_conformer.py`, and would refuse a file carrying both vocabularies. A condition-file inspector would print, for a `molecules_path` or `prior_path` blob, the distinct identifiers, `k` per graph, which `CONFORMER_FIELDS` are present, whether `embedding` and `torsion_state` are there, the dtype of the float tensors against the run's default, and the `check_state_convention` discrepancy re-measured against a freshly built energy. And the dispatch surface is enumerable: a listing of which `ConformerTorsions` methods `MultiConformerTorsions` overrides, which it inherits unchanged, and which raise on a dispatcher, would say from the code alone which quantities are per-row today.
