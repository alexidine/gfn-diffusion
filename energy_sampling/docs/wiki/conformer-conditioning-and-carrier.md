A conformer run samples internal coordinates for one molecule in the unconditional case and for a set of molecules in the conditional one. Two mechanisms carry the set. The *carrier* is a fixed-width state layout holding molecules of different coordinate counts in one dense tensor, so the trajectory, the losses and the buffers stay rectangular. The *condition channel* tells the policy, the flow head and the energy which molecule each row is. The stack is mid-refactor.

Left out and named: the chart and the internal-coordinate measure are [conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md); the graph encoder is [molecule-encoder](molecule-encoder.md); the losses and stages are [conformer-training](conformer-training.md); condition-grouped objectives and per-condition log Z are [conditional-route](conditional-route.md).

## The carrier layout

A molecule's state is `cat[r, theta, phi]` over the columns surviving at the run's level, so its width `k` and which columns wrap both vary. `energies/conformer_carrier.py::CarrierLayout` reads each member energy's per-column `_free_block` code (0 r, 1 theta, 2 phi, 3 transverse) and maps it to one of three regions through `energies/conformer_carrier.py::REGION`: r, theta and phi to their own, and a transverse column, either component $u$ or $v$ of a linear bend ([conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md)), to theta. A code outside 0 to 3 raises `ValueError`. The three region widths are the per-region maxima over members; a member's column `j` goes to `offsets[region(j)]` plus its rank within that region; `K` is the width sum, and the member's other columns are pads. `.free_block` holds each carrier column's region code, and `.block_width` the three widths.

Two properties follow from the region ordering. The periodic mask is column-constant, since the phi region holds only phi columns and every one of them wraps for every member, so the single `angular_mask` the GFN is constructed with remains correct for every member; the transverse columns share the theta region's box wall and `delta_theta_max` scale. And when every member has the same `_free_block` array, `.is_identity` is true, column `j` maps to `j` with `K = k`, and the layout changes nothing; this is decided on the member codes before any placement, so a set of members with identical codes, transverse ones included, keeps the identity, and a set whose members disagree on any column's code does not. On the identity `.free_block` is the region code in the members' own column order. A non-identity carrier can have no pads: two members of equal size whose transverse columns sit at different positions, such as `OCCCC#N` and `OCC(C)C#N` at `full`, share every region width, so `K = k` for both and the map is a permutation.

The region code does not record which columns are transverse. `.kinds` keeps, per member, a `[K]` array of the member's own code at each of its carrier columns and $-1$ on its pads (`.kind(ident)`), because one theta-region column can be one member's $\theta$ and another's $u$. `.column_kinds` lists the member codes occupying each carrier column and `.column_label` renders them as text, such as `theta|transverse`; `conformer_modeller.py::ConformerModeller._domain_figs` titles a carrier column with `.column_label`.

`.to_carrier` places a `[n, k]` member state into `[n, K]` with pads at exactly zero and `.from_carrier` is an `index_select` back, so it is differentiable; `.valid`, `.pad_cols` and `.col_map` express the same map as masks and index tables.

## Building a condition set

`build_conformer_conditions.py::build_member` is the per-molecule step of both builders. It constructs the member `ConformerTorsions` from a SMILES and the energy kwargs, then raises `MemberRefused` carrying a code from `::REASON_CODES` at the first check the molecule fails, in this order; an exception raised anywhere in it that is not a `MemberRefused` becomes one, with the code `::classify_failure` gives its text (`other`, message kept, when no pattern matches):

1. construction, whose exception text maps to `lt4_atoms`, `mmff_typing`, `incomplete_chart_full`, `theta_box`, `r_box`, `transverse_box` (a transverse bend that can reach $\rho \ge \pi$ in the box, or $\rho \ge \pi/2$ when it anchors a dummy frame), `no_free_dof`, `graph_broken` for a disconnected perceived graph, or an embedding failure. A `ChartRefused` takes instead the code `::_CHART_CODES` maps its `code` to: `incomplete_chart_full` for `incomplete_chart`, and the code itself for `wholly_linear`, `cumulated` ([conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md)) and the five stereo-lock refusals ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)). An embedding failure is `embed_failed_realisable` when `::untagged_realisations` (ETKDGv3 on the stereo-free constitution at the member's seed and the next three, MMFF-relaxed, re-perceived from 3D) produces the requested stereoisomer, else `embed_failed`;
2. at `torsion`, `mask` and `_M` disagreeing on the column count (`chart_defect`); at `full`, any held row (`incomplete_chart_full`);
3. a bond graph from `infer_bond_index` on the reference that differs from RDKit's (`graph_broken`), compared by `::_bond_graph_mismatch` through the member's `bond_index_slot` and `spec.perm`. This catches a graph that stays connected, which the constructor accepts (`tests/conformer/test_build_conformer_set.py::test_connected_graph_mismatch_is_refused_by_build_member`);
4. with the energy kwargs' `stereo_coeff` above zero, `energies/stereo_lock.py::thermal_check` finding a sample in a band (`stereo_lock_in_band`, [conformer-force-field-and-prior](conformer-force-field-and-prior.md));
5. with `carrier`, a one-member `CarrierLayout` that raises. It places a transverse column in the theta region and raises only on a block code outside 0 to 3, which no pattern classifies (`other`);
6. `condition_from_energy` (`closure_encoding`, a ring closure with no free endpoint), then `check_state_convention` and, with `carrier`, `check_carrier_convention` on the condition padded into the one-member layout (`convention_check`);
7. stereochemistry: a tetrahedral N tag is `stereo_n_tagged`; a SMILES that `::enumerate_stereoisomers` expands to more than one stereoisomer is `stereo_unspecified` (`::unspecified_stereo`); a reference whose `::stereo_identity`, read after `AssignStereochemistryFrom3D` on the H-stripped member molecule, differs from that of the SMILES as parsed is `stereo_verify_failed`;
8. the encoder embedding, fed the SMILES as given (`encoder_alignment`).

`::stereo_identity` is the pair (fixed-H InChI, CIP signature). It first strips tetrahedral N tags, clears legacy `_CIPCode` props, runs `rdCIPLabeler.AssignCIPLabels` and drops every chiral tag and double-bond stereo the labeller leaves unlabelled; the CIP signature is the sorted list of labels keyed by stereo-free canonical atom rank. No comparison of stereoisomers goes through a re-written SMILES.

`::stereo_mol` makes hydrogens explicit only on a doubly bonded atom whose one other substituent is a hydrogen. With every hydrogen explicit, RDKit's `EnumerateStereoisomers` returns one isomer for 1,4-cyclohexanediol; with none, one for an =NH imine (`tests/conformer/test_build_conformer_set.py::test_stereoisomer_enumeration`). `::stereoisomer_classes` counts the assignments of the open elements with `GetStereoisomerCount` and raises above 1024, runs `EnumerateStereoisomers` with `onlyUnassigned`, strips tetrahedral N tags, writes each isomer hydrogen-stripped as a canonical SMILES and re-writes it once, and groups the strings by the `stereo_identity` of the string as parsed. It adds, for each string, the SMILES of its labeller-filtered form when that parses to the same identity. A group's name is its string with the fewest stereo marks, ties broken lexically; the group's other strings are returned beside it. `::enumerate_stereoisomers` returns the sorted names. The stereo functions pin RDKit's legacy perception for their duration (`::legacy_stereo`).

`build_conformer_conditions.py::main` takes a SMILES list, defaults to `full` and `mmff`, takes the energy kwargs from `--config`'s `energy_config` when given (the `ConformerTorsions` signature filter of `::energy_kwargs_from_config`), prints every refusal grouped by code and writes the rest. With `--manifest` it also writes `manifest.json` beside `--out` (`::write_manifest`), the manifest `configs/conformer_cond/make.py` reads for a validation rung ([battery-generation](battery-generation.md)). Above `torsion` its prior goes through `energies/conformer_prior_draw.py::draw_member_prior`, which requires the fitted InternalPrior; the torsion-tier `::draw_prior_states` raises at any other level.

`build_conformer_set.py` builds a train and a held-out set from QM9 by file index. `build_conformer_database.py` plans its universe with the same `::read_source`, `::pool_rows` and `::plan_split` under the same defaults ([conformer-training](conformer-training.md)).

- **Encoder pool.** `--pool-need` defaults to 0, and `::pool_rows` then returns an empty pool ending at index 0, recorded under the rule `::NO_POOL_RULE`, whose text says that no encoder pool is excluded and every row is in the universe. The universe is then every row of the source except the rows `::plan_split` refuses (duplicate keys). A positive `--pool-need`, or `--pool-from-encoder`, which derives it from the encoder's metadata and refuses a positive `--pool-need` that disagrees, excludes a pool. `::encoder_pool` matches the checkpoint's `(arm, seed, n_train, best_step, best_heldout)` to exactly one row of one results file in the directory above the checkpoint's, and refuses otherwise. It recomputes `need = int((max(sizes) + n_test) * 1.1) + 64`, the expression in `models/encoder_probe.py::main`; for `mp+attn+spd_n20000_s0.pt` the row is in `encoder_final2.json` (`sizes` [20000], `n_test` 3000), giving 25,364. `::pool_rows` replays `encoder_probe.load_qm9`'s selection, the first `need` distinct raw SMILES in file order, on a source that starts at index 0, and otherwise uses the indices `[0, need)`.
- **Split.** `::plan_split` keeps rows from `--index-min` (default and minimum: the pool's end, 0 without a pool), refuses a row whose `::constitution_key` occurs in the pool (`encoder_pool_key`), keeps the lowest index of a repeated key (`duplicate_key`), puts a key on the held-out side when `::split_hash` modulo 1000 is below `--heldout-permille`, and sorts each side by that hash. `::constitution_key` is `encoder_probe.parent_skeleton` applied after explicit hydrogens are removed, so an imine identifier's `[H]` keys with its molecule.
- **Rungs.** `::walk_side` walks a side in hash order and keeps the first `n` molecules that yield a condition, so a smaller `--n-train` or `--n-heldout` gives a subset of a larger one (`tests/conformer/test_build_conformer_set.py::test_rungs_nest`).
- **Stereoisomers.** `::stereo_plan` takes the names of `stereoisomer_classes` and maps each to the name whose `stereo_identity` is that of `encoder_probe.mirror_smiles` applied to it; the group's other strings become isomer rows with the code `duplicate_stereoisomer`. `::build_molecule` orders the names by a salted hash and builds each with `build_member`, following a built isomer with its mirror when that is another name. The walk stops at `--max-stereoisomers-per-molecule` conditions (default 2), or at a refusal whose code is in `::CONSTITUTION_CODES` when no isomer has built yet. That set is `lt4_atoms`, `mmff_typing`, `no_free_dof` and `chart_defect`; `closure_encoding` and `incomplete_chart_full`, whose causes depend on the spanning tree and so on the atom numbering of each isomer's SMILES, are not in it. A molecule with no built isomer is recorded under a constitution code if one occurred, else the code its isomers shared, else `embed_failed_realisable` if any isomer had it, else `no_buildable_stereoisomer`. Each condition's identifier and SMILES are its name. The two members of a mirror pair are separate seeded ETKDG embeddings of their own SMILES, not reflections of one reference.
- **Layout.** One `CarrierLayout` over the training and admitted held-out members writes `conditions_train.pt` and `conditions_heldout.pt`; the run's `MultiConformerTorsions` builds its layout from the training file alone (`conformer_modeller.py::ConformerModeller._condition_set_molecules` reads `cfg:molecules_path`). `::admit_heldout` drops, after the walk, a held-out molecule whose one-member region widths exceed the training maxima (`heldout_wider_than_train`), and one whose members, added to the training members, give a `CarrierLayout` that places a training member differently from the training-only one (`heldout_moves_train_layout`). `::train_placement_change` makes that comparison: the same `K`, the same `.free_block` and the same `.cols` for every training member. Equal widths do not imply it. A training set whose members share one `_free_block`, such as the two enantiomers of `CC(O)C#N` with the transverse $v$ among the phi columns, keeps the identity layout; adding `CCO`, which fits inside its widths, makes the shared layout a region-ordered carrier that moves $v$ into the theta region, while the run's identity layout wraps that column as a phi (`tests/conformer/test_build_conformer_set.py::test_heldout_that_moves_the_training_placement_is_dropped_and_named`). A larger training rung can only widen the maxima or end the training identity, so the held-out rungs still nest. `::main` repeats the comparison over the whole admitted set and exits on a difference, then verifies `conditions_train.pt` and builds and verifies `prior_train.pt` against the training-only layout, and verifies `conditions_heldout.pt` against the shared one (`tests/conformer/test_build_conformer_set.py::test_training_file_is_checked_against_the_layout_the_run_rebuilds`).
- **Verified writes.** Each file is written under a temporary name, re-read, and renamed only if it agrees with the `CarrierLayout` it is checked against (`::verify_conditions_file`): the training-only layout for the training file, the shared layout for the held-out file. `::rebuilt_layout` reads `K` from `n_torsions` and each row's owned columns, in ascending order, from `state_mask`; they must give the layout's `K`, the manifest's identifier order, per-member `k` and pad count, and for each row the columns `energies/conformer_carrier.py::CarrierLayout.valid` returns, the comparison `energies/multi_conformer.py::MultiConformerTorsions._resolve_rows` makes at run time. Each row's `ctree_r_col`, `ctree_th_col` and `ctree_ph_col` must equal the member's own map, read off its member-width condition graph, indexed through `energies/conformer_carrier.py::CarrierLayout.cols`. A member with transverse columns has carrier columns out of member order, and on a carrier that is a permutation with no pads only this map comparison separates the layout's order from ascending order (`tests/conformer/test_build_conformer_set.py::test_file_disagreeing_with_the_manifest_is_refused`). The training file must also have a member on every column. With `--prior-rows-per-condition`, `prior_train.pt` holds that many `draw_member_prior` rows per training condition, each state cast to `--prior-dtype` (default float32) before it is scored; `::verify_prior_file` checks width, zero pads and row counts, and re-scores every row from its stored state and requires the result, cast to the storage dtype, to equal the stored energy bit for bit, before the rename.
- **Database prior.** With `--database` (a `build_conformer_database.py` output directory; it excludes `--prior-rows-per-condition`), `prior_train.pt` holds each training condition's lowest `--rows-per-condition-cap` (default 16) stored rows, in ascending energy (`::build_database_prior`). Before the walk, `build_conformer_database.py::refuse_other_member_kwargs` exits when the database was built under other member-defining arguments. After it, `build_conformer_database.py::read_conditions` reads the training identifiers' records, and `build_conformer_database.py::match_rows` measures each record's stored positions into this build's member, matching by identifier, member signature and placement `z`, and re-scores them; a condition absent from the database, refused there, of another signature, with a row outside the member's box, or re-scoring more than `--database-rescore-tol` (default `::DATABASE_RESCORE_TOL`, $10^{-6}$ kcal/mol) from the stored energy has no rows, and is written to `prior_refusals.tsv` with its code from `build_conformer_database.py::MATCH_CODES`. Each state is cast to `--prior-dtype` before it is scored, and the stored energy is that re-score. `::verify_prior_file` then takes the per-condition row counts and the conditions with rows. The manifest's `prior` block records the source, the database's path, `run_hash`, `header_hashes_sha256`, member arguments and set-builder defaults, the cap, the tolerance, the row total, the refusals by code, the worst re-score gap, the largest reference-geometry gap, the count of conditions whose reference is more than $10^{-5}$ Å from the database's, a histogram of rows per condition and per-condition statistics (`tests/conformer/test_conformer_database_cut.py`).
- **Records.** `manifest.json` holds the source path and sha256, the pool reconstruction, the energy kwargs and config sha256, the encoder sha256, the split, the seeds, `K`, the region widths, `offsets` (null on an identity layout), `is_identity` for the shared layout and `train_only_is_identity` for the training-only one, which can differ when the training members share one region-ordered `_free_block` and a held-out member's codes differ, every member with its `k` and pad count, the mirror pairs, reason counts per molecule and per isomer, git HEAD, library versions and the sha256 and size of every artifact. `split.tsv`, `molecules.tsv` and `rejections.tsv` are written beside it; `molecules.tsv` gives each condition's one-member region widths (`blocks`, $u$ and $v$ counted in theta), its count of transverse columns (`n_transverse`), its `reference_energy` (the member's potential at state 0, T = 1) and its `encoder_group`, the lowest isomer rank with a bit-identical frozen embedding.

## Handling of the pad columns

- `models/conformer_gfn.py::ConformerGFN._pin_dead` writes pads to zero through `torch.where`, so a NaN in a pad becomes zero rather than propagating. `._bind_state_mask` raises when the GFN is flagged `_carrier` and the batch carries no `state_mask`, and the prior-jitter path in `conformer_modeller.py` masks its noise the same way.
- `ConformerGFN.gauss_logprob` and `._pb_logprob` apply the per-row `state_mask` to the per-dimension terms before the sum over dimensions; the exact backward mixture is recomputed in `._pb_mixture_ang_terms`, a replica of the shared-file method without its final sum. `gauss_logprob` raises when dead latent rows and a carrier state are both present.
- `ConformerGFN.fwd_gauss_logprob` raises when a DPLR low-rank factor is present and the GFN is flagged `_carrier` or has a `state_mask` bound. The parent's Woodbury path sums over all `K` columns and never calls the masked `gauss_logprob`, so pad columns would otherwise enter log P_F. The parent calls it from the forward, backward, replay and implied steps, so the refusal fires at the first P_F log-prob evaluation in any of them.
- `energies/multi_conformer.py::MultiConformerTorsions._resolve_rows` refuses, before any scoring, a row whose pad columns are not exactly zero, a batch whose `state_mask` disagrees with the layout, on a carrier a batch carrying no `state_mask` at all, a `mol_id` naming no member, and a row whose atom count, placement-order `z`, per-atom `ctree_transverse` flag or per-atom `ctree_dummy_frame` flag differs from its resolved member's. The `z` comparison is the only one of these checks that sees a `mol_id` registered to the wrong member between two molecules with identical block counts, such as the constitutional isomers CCCO and CC(C)O. The flag comparison is atom by atom against the library's flags (`energies/ff_library.py::ForceFieldLibrary`, written by `energies/conformer_data.py::transverse_atom_flags` and `::dummy_frame_atom_flags`, the functions `condition_from_energy` writes the fields with), in the same reduction as `z`, so a file whose flags sit on different atoms of the right molecule, even the same number of them, is refused with a message naming the flags; a batch without a field reads as free of that flag. When the `stereo_coeff` keyword of the energy is above zero, a row is also refused when its per-atom stereo-lock code, `ctree_stereo_kind` times `ctree_stereo_sign`, or its quad `ctree_stereo_nbr` differs from the library's (`ForceFieldLibrary.stereo_code`, `.stereo_nbr`, written by `energies/stereo_lock.py::atom_codes`); two stereoisomers of one molecule share `z`, atom count and every chart flag, so this is the comparison that separates them, and a batch without the fields reads as carrying no lock element. Whatever the coefficient, a row is refused when its per-graph `ctree_stereo_coeff`, the coefficient of the energy its condition graph was built from, differs from the energy's (`energies/conformer_data.py::stereo_coeff_mismatch`; a batch without the field reads as 0). The per-atom stereo comparison compares the stored quad exactly; `stereo_lock.py::_best_quad` resolves candidates within `TIE_TOL` of the largest by candidate index rather than by value, so symmetric substituents do not leave the stored quad to roundoff in the reference. The checks are reduced together and read back in one host sync per call. `_resolve_rows` does not compare the batch's `n_torsions` with the width of `x`, and `energies/conformer_data.py::state_to_dof` reshapes `x` to the batch's width, so on an identity-layout batch without `state_mask` the state width is not checked.
- On a carrier, `MultiConformerTorsions` is a dispatcher rather than a chart, every inherited chart method named in `multi_conformer.py::_CHART_METHODS`, among them `potential_energy`, `build_positions` and `prior_log_prob`, raises.

## The policy pools the ragged columns; the energy dispatches per row

`MultiConformerTorsions` subclasses `ConformerTorsions` and holds one member chart per identifier, the first being the reference member. `.energy` scores a mixed batch in one pass, `._energy_one_pass`, with no loop over molecules. The tree and each row's $(r, \theta, \phi)$ come off the condition graphs through `energies/conformer_data.py::batch_tree` and `::state_to_dof`; on a carrier the remapped `ctree_{r,th,ph}_col` already point at each row's own columns, so nothing is sliced back to member width. The force field is gathered per row by `energies/ff_library.py::ForceFieldLibrary.gather` from every member's single-copy `ff_single`, packed at construction by `ForceFieldLibrary.from_members`; an optional term (torsion, stretch-bend, out-of-plane) that no row of the batch carries is emitted as `None`, as a member without it holds it. The box wall runs over the layout's non-phi columns, where the zero pads contribute exactly zero; `log_jacobian` runs on the mixed tree; and `log_chart_jacobian` is the per-member constant looked up by library index, not the graph-derived sum of log scales, which overcounts at `torsion`, where one column drives several dihedral rows. Rows resolve to library entries by `mol_id` through the table `.bind_identifier_registry` builds, with `identifier` as the fallback. A batch whose float fields are not in the energy's `dtype` is refused. `.member_groups` returns each present molecule's rows for per-member work, and `._energy_per_member`, a loop over members through each member's own `energy`, is a test oracle; outside the tests only that oracle calls `member_groups`. A carrier state with `mol_batch` absent raises in `energy`; with one chart, or with no `mol_batch` on an identity layout, the call falls through to the parent.

Transverse rows take the member's own treatment. `mxtaltools/conformers/builder.py::build` and `::log_jacobian` receive the per-angle-row mask `energies/conformer_data.py::transverse_mask` reads off `ctree_transverse`, and `log_jacobian` also receives $\phi$, so a transverse row is built by `place_nerf_transverse` and measured as $\log\mathrm{sinc}\,\rho$; a batch with no flagged atom passes `None` and takes the code path it took before. `build` also receives the per-torsion-row mask `energies/conformer_data.py::dummy_frame_mask` reads off `ctree_dummy_frame`, so a dummy-frame row is placed against the same Z-matrix dummy atom as in its member ([conformer-chart-and-internal-coordinates](conformer-chart-and-internal-coordinates.md)); `log_jacobian` receives no such mask, and `None` again leaves a batch without such a row on its previous path. `._disc_wall` adds the disc term of `ConformerTorsions.bounding_energy` to the box wall before the temperature pre-multiplication: on each flagged atom it takes $u$ from the atom's $\theta$ slot and $v$ from its $\phi$ slot of `state_to_dof`'s output, forms $\rho = \sqrt{u^2+v^2}$, and sums `bounding_coeff` $\cdot\,\mathrm{relu}(\rho - \rho_{\text{wall}})^2$ into its row by `index_add`. It raises when the $u$ and $v$ selections differ in length. `._build_library` raises when any member's `bounding_coeff`, `rho_wall`, `energy_clip` or `stereo_coeff` differs from the dispatcher's, the values the one-pass energy applies to every row. With `stereo_coeff` above zero the one-pass energy adds the stereo lock ([conformer-force-field-and-prior](conformer-force-field-and-prior.md)) to the gathered force field's energy before the clip, computed by `energies/stereo_lock.py::batch_lock_energy` from each row's own `ctree_stereo_kind`, `ctree_stereo_sign`, `ctree_stereo_nbr` and `ctree_stereo_lo`, the fields `energies/conformer_data.py::condition_from_energy` writes through `stereo_lock.py::graph_fields` whatever the coefficient; they are in `energies/conformer_data.py::CTREE_ATOM_FIELDS`, so a file without them is refused at collation. `tests/conformer/test_stereo_lock.py::test_one_pass_equals_the_member_oracle_with_stereoisomers_in_the_set` compares the one-pass energy and the baked potential with each member's own on a carrier set holding an enantiomer pair, a diastereomer pair and an E/Z molecule, and `::test_a_mol_id_bound_to_the_other_stereoisomer_is_refused` exercises the refusal. `::test_one_pass_keeps_the_lock_inside_the_energy_clip` makes the oracle comparison on the same set with `energy_clip` at 300 kcal/mol, on states in the box, each the drawn state or its mirror image, whichever the lock penalises more, so that every row has a positive lock term and at least one row has both $U$ and the lock term above the clip; it also compares the baked potential with `log_rescale_positive` of each member's force-field energy plus lock term, and the prebuilt reward with the live one at $\log_{10} T$ of $-0.3$, 0 and 0.3. `.prebuilt_sample_to_reward` resolves rows the same way: at `flex` and `full` it recomputes log J from the stored states in one pass, with the same mask and $\phi$, and at `torsion` and `dihedral` it gathers each member's `log_jacobian_const`. `tests/conformer/test_alkyne_chart.py` makes the same energy, gradient and prebuilt-reward comparisons on a carrier set holding two alkynes with dummy-frame rows. `tests/conformer/test_transverse_carrier.py` compares the one-pass energy, its gradient, the baked potential and the prebuilt reward with each member's own on a set of three nitriles and three molecules without a linear centre, at states with every $\rho$ between 1.0 and 1.4; no graph-native count of `ConformerTorsions.transverse_crossings` exists.

The reference geometry, the per-column scales and the clamp floors the one-pass energy reads are the conditions file's `ctree_*` fields, while the force field and `log_chart_jacobian` are the run-time member's. `energies/conformer_carrier.py::check_carrier_convention` and `energies/conformer_data.py::check_state_convention` compare the file with the member chart only when `build_conformer_conditions.py` writes the file; at run time `_resolve_rows` checks atom identity, the per-atom transverse and dummy-frame flags, the recorded stereo coefficient and, with the stereo lock on, the per-atom stereo-lock code and quad, and nothing else about the chart.

`._energy_one_pass` casts `x` to the energy's `dtype` and computes in it. A member constructed with `dtype=None` builds `ref_pos`, `_M`, `_ref_dof` and `_free_scale` from float64 arrays with that argument rather than with `self.dtype`, so under a float32 default they are float64, and the oracle `_energy_per_member` and the one-pass path do not compute in the same precision.

The rollout stays dense `[B, K]`. `models/ragged_set_policy.py::RaggedConditionalSetPolicy` is the only object seeing ragged data: it gathers the valid columns flat with `flat_idx`, pools them with `segment_softmax` and `segment_sum` over `dof_batch`, and scatters back to `[B, 2K]` contiguous blocks with pad outputs zero, so `GFN.split_params` is unchanged. Per-column identity is the batch's `dof_static` concatenated with the learned `set_policy.py::DoFCorrelator` over the embeddings of the atoms a column spans, and the pooled molecular embedding joins `rho`'s context. Both index vectors are bound once per trajectory in `ConformerGFN.bind_molecular_conditioning`, called from the three `get_traj_*` entry points, which also shifts `dof_atoms` by the batch's `ptr` offsets, those indices being in local tree numbering.

## The set head in a checkpoint

The set head is swapped in after `GFN(**gfn_config)` is built, so its architecture is not among the GFN constructor's arguments. `conformer_modeller.py::ConformerModeller._install_set_policy` stamps what it built into `gfn_config['conformer']`, which a checkpoint stores with the rest of `gfn_config`:

- for the ragged head, every argument it is built from except `zero_init`: `policy_kind`, `set_policy_hidden`, `set_policy_layers`, `set_policy_corr_dim`, `n_static`, `enc_dim`, `mol_dim`, `frame_size`, `norm`, `dropout`, `carrier` and `block_width`;
- for a dense set head, its sizes, `mol_dim` and `carrier: false`, which name it but do not suffice to rebuild it;
- for a flat policy on a carrier, `{policy_kind: flat, carrier: true, block_width}`. A flat policy off a carrier writes no block.

Each of these blocks, when the energy holds a member set (a `MultiConformerTorsions`), also carries `condition_set`, added by `ConformerModeller._with_condition_set` from `._condition_set_identity`. Its `identifiers` are the members' identifiers sorted, the order in which `train.py::Modeller.init_identifiers` numbers the identifiers of every dataset it reads, so entry $i$ is the identifier whose `mol_id` is $i$. Its `signatures` hold, per identifier, the BLAKE2b digest of 8 bytes (16 hex characters) that `ConformerModeller._member_signature` takes of three fields of the built member: the SMILES the conditions file gives it, its per-column block codes `_free_block` in state order, and its placement-order atomic numbers `spec.z`. Its `signature_recipe` is the string `ConformerModeller._MEMBER_SIGNATURE` naming that digest. A single chart, a `ConformerTorsions`, writes no `condition_set`. Once the registry exists, `ConformerModeller.init_identifiers` calls `._assert_registry_is_the_stamp`, which raises `ValueError` when the registry's identifiers in `mol_id` order are not the stamped list, naming the identifiers found on one side only.

On a fresh build `._install_set_policy` passes `cfg:model.zero_init` (the `zero_init` entry of `gfn_config`) to whichever set head it builds, ragged or dense. With it true the head's `rho.output_layer`, a linear layer without bias, is zeroed, so the untrained head outputs 0 for every input; with it false the layer keeps its random initialisation. `.gfn_from_config` rebuilds the ragged head through `._ragged_policy_from_stamp` with `zero_init` false before the checkpoint's weights load. `tests/conformer/test_set_policy_zero_init.py` checks the output layer of all three heads under both values, and the zero output of the untrained dense head.

`checkpointing.py::Checkpointer._build_gfn` calls `ConformerModeller.gfn_from_config` on both load paths, `load_full` and `load_weights_only`. It builds the model the stored `gfn_config` describes before the strict `load_state_dict`: `GFN` for a flat policy, `ConformerGFN` flagged `_carrier` for a flat policy on a carrier, and `ConformerGFN` with the ragged head rebuilt from the stamp. A stored dense set head raises `NotImplementedError`. The block is popped from a copy, so `gfn_config` keeps it and the next save writes it again. Before building, `._assert_checkpoint_layout` refuses a checkpoint whose `dim`, periodic columns or stored `block_width` differ from this run's energy, and on a carrier run prints a warning when the checkpoint has no `block_width` stamp.

`ConformerModeller._assert_condition_set` runs next. It compares the stored `condition_set` with this run's, computed from the members `ConformerModeller.init_energy_function` built from `cfg:molecules_path`, and lists the identifiers only in the checkpoint, those only in this run, those whose position (their `mol_id`) differs, and, when the two `signature_recipe` strings are equal, those whose signature differs. `load_full` calls `_build_gfn` before it restores the modeller state, the buffer sidecar and `condition_log_z`, so on that path a non-empty list raises `ValueError` ahead of every restore. The message names each list, the first ten of a longer one with a count of the rest (`ConformerModeller._name_some`), and names two ways on: a fresh start, or `cfg:load_weights_only`. `ConformerModeller._loading_weights_only` tells the two loads apart by the branch `train.py::Modeller.init_gfn` takes: `cfg:checkpoint_name` with `cfg:load_weights_only` true is the weights-only load, while `cfg:checkpoint_name` alone, and `cfg:continue_from_checkpoint` whatever `cfg:load_weights_only` says, load in full. On the weights-only load the lists are printed on one line and the load continues. A set that matches prints one line saying so. A stored block without `condition_set`, or no block at all, prints one warning on a full load and nothing on a weights-only one, and a run whose energy is a single chart compares nothing. `init_identifiers` numbers the sorted identifiers, so a conditions file listing the same members in another order gives the same list and loads. `tests/conformer/test_condition_set_identity.py` checks each refusal with the three restores spied, the requeue branch, the reordered file, a permuted stamp, the one-line weights-only notice, the warning and the registry check.

After a load, `._install_set_policy` swaps nothing. `._check_reloaded_policy` compares this config's `policy_kind` with the stored one, then every field a fresh build of this config would stamp with the stored field, and raises naming the first mismatch; on a reloaded flat policy over a carrier it calls `._flat_on_carrier`. A checkpoint without the block is read as flat. For a set head its closing line prints that the EMA and optimizer state are as restored on both load paths, including `load_weights_only`, after which `train.py::Modeller.init_gfn` builds the optimizers fresh. `ConformerModeller._restamp_condition_set` then sets the block's `condition_set` to this run's, so the next save stores the set this run registers; a checkpoint with no block, reloaded flat onto a carrier, gets the block a fresh build of that policy writes.

The dense `conditional_set_policy_for` head binds the energy's reference member's per-column features at construction. `._needs_ragged_policy` therefore selects the ragged head on a carrier and on any set of more than one distinct SMILES, an identity layout included, and the modeller then flags the GFN `_carrier`, so a batch without `state_mask` is refused at binding. The conditions file has to carry `state_mask` and `dof_static`, which `build_conformer_conditions.py --carrier` writes for an identity layout too.

`ConformerModeller.scramble_applicable` returns false, with a one-time notice, when the forward policy is a conditional set head (`wants_molecular_conditioning`). That head reads the molecule through its own bindings and never sees the scrambled `s_emb`.

`._refuse_compiled_set_policy` refuses `cfg:compile_policy` under `cfg:model.policy_kind` `set` unless the setting is one of `False`, `None`, `0`, `'off'` or `'false'`. The base `init_gfn` calls `Modeller.maybe_compile_policy` before the swap on a fresh build and after the rebuild on a reload. `maybe_compile_policy` enables compilation for any truthy setting other than `auto` and `step`, so the quoted strings `'off'` and `'false'` pass the refusal and compile.

## The condition channel

`energies/conformer_torsions.py::ConformerTorsions.condition_samples` returns `(mol_batch, log_T_tensor, condition, condition_id)` and attaches `conditions` and `condition_id` to the batch. The condition vector is log-temperature when `cfg:temperature_conditioning` is on, followed by the per-graph `embedding` when `cfg:embedding_conditioning` is on; with neither, one zero column. A batch missing `embedding` under that flag raises, and the width is checked against `cfg:embedding_conditioning_dim`. Conditions are drawn per group of `repeats` and broadcast within it. `condition_id` is `mol_id * (n_sg * n_zp)`, which with `n_sg = n_zp = 1` equals `mol_id`. A batch without `mol_id` raises once `condition_library_size` exceeds 1, before the temperature draw consumes the RNG; at 1, the single-molecule route, its `condition_id` is zero (`tests/conformer/test_conformer_chart_guards.py::test_set_refuses_a_batch_without_mol_id`, `::test_single_molecule_route_still_defaults_to_condition_zero`).

The identifier namespace has three levels. `identifier` is a Python list on the batch and the key `train.py::Modeller.init_identifiers` mints the registry from; `mol_id` is that registry's integer, a graph attribute and the only form surviving a buffer, since buffers keep tensors; `condition_id` sizes the per-condition log Z table through `ConformerTorsions.set_n_molecules`, which writes `condition_library_size`. `ConformerModeller.init_identifiers` hands the registry to `MultiConformerTorsions.bind_identifier_registry`, which builds the `mol_id`-to-library-index table the energy resolves rows through and lets `._row_identifiers` resolve a buffered row from `mol_id` alone; without it that row raises rather than falling back to the reference member.

Embeddings are baked offline. `models/encoder_cache.py::embed` runs the frozen encoder on the 2D graph, returning per-atom `h` and pooled `g`; the cache is stamped with the checkpoint's sha256 and refuses to load against another. `build_conformer_conditions.py` writes `embedding`, `atom_embedding`, `dof_atoms` and `dof_mask` onto each condition graph, the last two padded to a file-wide row count `R`. With `--carrier` it re-expresses every graph through `carrier_pad_condition`: the reconstruction columns `ctree_{r,th,ph}_col` are remapped, `n_torsions` becomes `K`, `state_mask` and `dof_static` are written, and `dof_atoms` and `dof_mask` are written in carrier form there instead. `ctree_state_col` is not remapped, since it indexes rotatable axes rather than state columns. `check_carrier_convention` then asserts the padded graph rebuilds the member chart's own geometry.

## `scalar_flow`

`conformer_modeller.py::ConformerModeller._build_gfn_config` sets `scalar_flow` true, from the conditions file rather than a config key, when the run is conditional and the set read off `cfg:molecules_path` has exactly one distinct identifier. `models/gfn.py::GFN.init_flow_model` then builds a `LearnableScalar` in place of the conditional `scalarMLP` over the condition embedding. `train.py::Modeller.z_level_fill` writes `flow_model.scalar.data`, which a `scalarMLP` does not have; `bootstrap_z_by_rollout` reads that scalar either side of a fill, and the stage-entry bootstrap in `protocol.py` writes it on both the live and the EMA model.

## The log Z(c) head

`models/conformer_gfn.py::ConformerGFN.install_flow_head` chooses what the conditional log Z head reads.

- `'condition'` is the default and is a no-op. The head is `GFN.init_flow_model`'s `scalarMLP` over the conditioner output, which `GFN._condition_flow` reads detached.
- `'mol_emb'` replaces `flow_model` with `models/conformer_gfn.py::MolEmbFlowHead` under the same attribute name, so every router keyed on `flow_model.parameters()` picks it up. The new head reads the batch's pooled `embedding`, `mol_dim` wide. When `column_blocks` is given it also reads each row's count of valid columns per block code present, taken from the bound `state_mask` (all columns when none is bound); the block assignment is a non-persistent buffer, so a checkpoint carries the head's weights and not its column layout. The assignment is one code per column for every row. On a carrier the energy's `_free_block` is the region code, under which a transverse column counts as theta, while on a single molecule it is the member's code, which counts it as transverse; the per-member codes on a carrier are `CarrierLayout.kinds`, which the head does not read. It copies depth, width, norm, dropout, activation and bias from the head it replaces. It replaces the module in place: optimizers and an EMA copy built before the install still hold the replaced head's parameters.

`ConformerGFN._bind_flow_input` binds this input detached, once per trajectory, in each of the three `get_traj_*` entry points. `ConformerGFN._condition_flow` reads the binding and consumes it, so a trajectory that reaches the head without its own binding raises instead of reading the previous batch's molecules. `get_traj_fwd` puts the same input in `_z_cal_embedding`, so z_calibration's regression mode feeds the head its own input.

The install refuses an unknown kind, a second install, an unconditional model, `full_flow`, a head that is not a `scalarMLP` (the `LearnableScalar` of `scalar_flow`), a missing or non-positive `mol_dim`, a `column_blocks` whose length is not the state width, and an input width equal to `condition_embedding_dim`. The head's forward refuses any other input width. `train.py::Modeller.bootstrap_log_z` (protocol action `bootstrap_z`) calls `flow_model` on the conditioner output, so it raises under this head. A `condition=False` pass, a batch without `embedding`, and a bound input whose row count differs from the trajectory's also raise. Under `scramble_conditions` the head reads the true molecule, where the default head reads the scrambled conditioner rows.

No config key selects the head, `gfn_config` records nothing about it, and nothing outside the tests calls `install_flow_head`.

## Determinism of the encoder input, and the atom-order contract

The encoder reads atom types, bonds and parity from the 2D graph and nothing else, so its output is fixed for the rollout and is cached rather than recomputed. The tree is built with `spec_from_graph(..., use_geometry=False)`. Linearity flags are separate: `ConformerTorsions.linearity_source` is `'mmff_typed'` when the force field is `mmff`, and `angle_is_linear` and `torsion_frame_is_linear` then come from MMFF's typed equilibrium angle at 179.99 degrees, a function of the graph. With any other force field the source is `'measured'` and the flags are read off the reference conformer, and the state width then depends on an embedded geometry.

The two paths order atoms differently: `models/graph_encodings.py::graph_from_smiles` takes RDKit's own atom order after `Chem.AddHs`, which appends the hydrogens after the heavy atoms, while the conformer path uses the tree's placement order. `embed` permutes the per-atom embeddings by `spec.perm` once, at build time, and when `z_tree` is passed it asserts `z_enc[perm] == spec.z` and raises on mismatch; `build_conformer_conditions.py` passes both.

## Could be tooling

`build_conformer_set.py` writes a manifest for a mixed-k set (layout `K` and block widths, each member's `k` and pad count, the encoder sha256, the energy kwargs, the RDKit version) and checks each file against it before writing; nothing at run start reads it. A preflight could compare the manifest with the config a run is launched under: the energy kwargs with the config's filtered `energy_config`, the encoder sha256 with the checkpoint named for the embeddings, and the recorded RDKit version with the one that will rebuild the members from SMILES; then rebuild the layout from the training file and assert it matches. The builder checks the training file against a training-only layout, but one built from its own member energies, not from the file's SMILES under the run's kwargs and RDKit. At run time `_resolve_rows` finds a mask disagreement one batch into training, and does not find a disagreement in column order alone.
