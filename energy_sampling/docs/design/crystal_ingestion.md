# Crystal ingestion contract for MXtalTools

**Status: PROPOSAL, 2026-10-20. Not adopted; no authority over code.** The detailed contract behind B6 of
`fd_mxt_integration.md` (the ASE-modelled user-facing shape the owner agreed). Built from a read-only survey of the
CSD featurizer, the stored schema, every consumer and three CIF readers, and checked claim by claim against the code.
Evidence and scratch scripts: `artifacts/fd_design_oct15/ingestion_survey/` (`pipeline/`, `schema/`, `consumers/`,
`cif/`, `designer/`, `checker/`). It respects `fd_tooling.md` §6: D1 (nonstandard settings re-expressed into the
standard one), D2 (off-sheet Z′ = 1 Sohncke rows get a mirrored reference), D3 (Z′ > 1 refused for FD work).

Paths: `mxt/` = `MXtalTools/mxtaltools/`; `con/` = `mxt/dataset_utils/construction/`; `cif/` = `con/cif/`;
`dc/` = `mxt/dataset_utils/data_class_methods/`; `fd/` = `mxt/crystal_fd/`; `gfn/` = `gfn_diffusion/energy_sampling/`;
`sv/` = `gfn/artifacts/fd_design_oct15/ingestion_survey/`. Tags: [code] read in the code; [measured] run, output named;
[inferred] a model fit or reasoning, not a measurement. Line numbers drift: `dc/crystal_analysis.py` was being rewritten
by another session on 2026-10-20, so its citations need re-checking before adoption.

## 1. Topline

**Today.** One script (`con/featurize_cif_chunks.py`) reads each CSD CIF through CCDC, one crystal at a time, and turns
about 40.8% of them into pickled single `MolCrystalData` rows. It has three serious faults: it copies unit 0's
conformer into every unit of a Z′ > 1 crystal; in protonated mode (how `new_prot_csd.pt` was made) it replaces every
deposited hydrogen with one regenerated by CCDC; and its June 2026 run silently lost 46 of 1,000 chunks (40,182 CIFs).

**The contract.** A cheap, CCDC-free reader (`MolCrystalData.read`, `MolCrystalData.from_arrays`) returns one batch,
each row with a status instead of an exception. Seven named steps run on that batch, each with explicit choice
arguments; a convenience call runs a named preset of them. The stored product keeps the deposited atoms, each unit's
own conformer and the CSD provenance, so the open policies (hydrogens, handedness, near-face, dedup) re-run without
parsing CIFs again.

**Two findings shape it.** No consumer accepts a batch without a pose (the unit-cell builder, the ELJ energy and the FD
importer all need pose parameters), so "bare" and "posed" are two named states. And keeping per-unit conformers
exposes a live defect: `canonicalize_zp_aunits` reorders pose slots but not atom blocks, which already affects the
pre-copy files' Z′ > 1 rows and must be fixed before any such row reaches GFN.

**Decisions for the owner** are in §7: hydrogens, whether CCDC stays in the bulk CSD chain, Z′ < 1 and multi-component
crystals, re-expression into the standard setting, CIFs without an operator loop, and the 46 missing chunks.

## 3. Simple level

**Built 2026-10-20** (migration step 1, reader part): `mxt/dataset_utils/data_class_methods/crystal_io.py` (mixin
`MolCrystalIO`, wired into `MolCrystalData`), `MXtalTools/tests/test_crystal_io.py` (59 tests), and one keyword-only
option in `cif/sites.py` (`refuse_partial_occupancy=True` keeps today's behaviour). The code is the reference; it
departs from the text below in: no `missing_ops` argument (replaced by the future `find_symmetry` step, §7a); extra
row statuses `z_prime_mismatch` and `bad_coordinates`; `x` is zeros and a caller's charges are refused until `done`
has a features bit; a pose with [B,3,3] lattice-row cells is refused; `select_rows(idx)` keeps rows by the slice
levels. Since built the same night: the level fix in `data_classes.py` (`subsample_new_batch`,
`rebuild_simple_slice_inc_`, `append_batch` read `_slice_dict` where a length is ambiguous; `tests/test_batch_levels.py`)
and the store (`crystal_store.py`: `save` / `load`, schema `mxtaltools.ingest/1`; `tests/test_crystal_store.py`). The
collate gate runs on all 100 rows of
`tests/datasets/mini_new_csd.pt`; `analyze` reads `crystal_analysis.py`, which another session was rewriting, so rerun
the gate after that lands.

```python
MolCrystalData.read(sources, format='cif', *, missing_ops='refuse', identifiers=None,
                    dtype=torch.float32, device='cpu', full=None, **format_options)
MolCrystalData.from_arrays(cell, xyz, z, *, ptr, sg, ops=None, setting=None, atom_attrs=None, **attrs)
```

**`read`.** `sources`: a path, a list of paths, or CIF text; each `data_` block becomes one row, and a file that
cannot be parsed still becomes a row with a status and no atoms, so every source maps to a row. `format`: `'cif'`
first. `format_options` map onto the native reader's flags. `full`: a named preset of the full chain (§4) to run after
reading; see §7 Q7 on whether `full=True` should mean a default preset.

**`from_arrays`.**
- `cell` [B,6] (Å, radians) or [B,3,3] lattice rows (then `xyz` is rotated into the T_fc frame); `xyz` [N,3] Cartesian
  Å, the deposited set (atoms the operators expand into the cell); `ptr` [B+1] required.
- `ops` are required, unless the caller passes `setting='standard'`, which takes `SYM_OPS[sg]` and records it. A
  default of `SYM_OPS[sg]` is refused: regenerating operators from the number moved ELJ on nonstandard rows
  (−991.0 to +4161.2 raw units) and changed the FD import of 18 of 29 such rows without a refusal [measured]
  `sv/schema/minimal_attrs_tail.out`.
- Attribute levels are declared: `**attrs` per crystal (leading dimension B), `atom_attrs` per atom (N). The levels are
  stored in a level map that `subsample_new_batch`, `rebuild_simple_slice_inc_` and `batch_to_list` read; today those
  infer the level from the length, which corrupts one-graph batches (`mxt/dataset_utils/data_classes.py:618-620`;
  [measured] `sv/schema/one_graph_subsample.out`).
- Pose attached: if `attrs` carry all of `z_prime`, `aunit_centroid`, `aunit_orientation`, `aunit_handedness`, `xyz` is
  the posed asymmetric unit and the batch is posed. `from_arrays` then checks `num_atoms % z_prime == 0`, computes
  per-unit radius, mass and molecular volume and stores the row sums (the latent's convention), and writes `x` as zeros
  with the `features` bit of `done` unset. A partial pose raises (a caller error). It never checks the pose itself;
  `check_rebuild` does when asked.

**Built as a batch directly**, without the per-row `__init__` or `collate_data_list`, following GFN's
`init_blank_crystal_batch` (`gfn/energies/molecular_crystal.py:1478-1542`). A probe built this way reproduced
`mol2ucell`, `mol2cluster`, `analyze(['reduction_en','elj'])` and `from_mol_crystal_data` exactly on 10 Z′ = 1 rows, and
ELJ on 8 rows including two Z′ = 2 [measured] `sv/schema/minimal_attrs_tail.out`. It must also match
`collate_data_list` attribute for attribute: `max_z_prime` a python int, `symmetry_operators` a list of arrays, python
bools as bool tensors, `_slice_dict` / `_inc_dict` (the buffer's `state_dict`, `batch_to_list` and `append_batch` read
them). Pad convention for unused unit slots: 0, as collate and `reparameterize_unit_cell` pad (`mxt/dataset_utils/utils.py:119-121`)
and as `gfn/tests/crystal/test_mirrored_rows.py:101` pins; the per-row constructor's pad of 1 (`data_classes.py:1250-1252`)
is not used.

Steps are `MolCrystalData` methods. Each returns a new batch and never mutates its input; rows whose status is not
`ok` pass through bit-identical; a row whose processing raises a `RuntimeError` or `ValueError` gets that step's code
(the step retries on halves, as `fd/canon.py` `_isolate` does), and any other exception propagates; bad arguments
raise; `done` is a bitmask of the steps that have run.

**Convenience call.** `read(paths, full=PRESET)` or `batch.run_chain(PRESET)`. A preset is a frozen object in code

derived product (§5). Cost of the new chain: unmeasured; today's CCDC route is about 0.12 s per CIF, about 31
process-hours for the dump.

**CSD-scale runner** `featurize_cifs(paths, out_dir, *, preset, chunk_size)`: writes the sorted path list and chunk map
first; skips a chunk only when its file and manifest exist with a matching code digest and preset; writes atomically
(temporary name, then rename); concurrent processes claim a chunk by atomic file creation and never wait on a claim;
`collate` refuses unless every mapped chunk is present (`allow_partial=True` explicit and recorded). Termination: each
process walks a finite list once; a crashed process's claims show in `collate` as claimed but unwritten and are freed by
an explicit `reclaim`, never by waiting. It fixes `if True:`, silent partial collation and refusal codes sent only to stdout.

**Outside the chain.** `dedup(key, keep, tol)`, all required: returns `duplicate_of` [B] (−1 for a representative)
and never deletes; `key` = `'refcode_family'` | `'molecule'` (unit graph hash) | `'canonical_form'` (after

missing value (temperature is absent for 33 of 300 sampled refcodes). It replaces the random pick at load. Symmetry
detection for P1 inputs (generator output) ports `p1_ingest.py:276-340`.

## 7a. Owner answers, 2026-10-20

- **Hydrogens (Q1): regenerate.** "I don't trust the locations in the CSD but only moderately trust regenerated ones …
  it has to be the latter though that might break some molecules." So the CSD preset regenerates H, and `sanitize`
  flags any row whose regenerated protonation differs from the deposited one (`hydrogen_count_mismatch`, per heavy
  atom), so broken molecules are visible rather than silent. Proposed refinement, not yet agreed: re-place H at ideal
  geometry on the heavy atoms that carry H in the deposited structure (positions regenerated, protonation kept), with
  CCDC's own protonation as the comparison.
- **CCDC (Q2): to be replaced** once the tooling matches it. Its main job today is identifying and featurizing the
  molecule graphs in the unit cell. Replacement needs: molecule graphs from distances under periodic boundaries (have
  prototypes), bond orders and formal charges, and hydrogen placement; adopted when a CCDC-free chain agrees with CCDC
  on a seeded sample (graphs, SMILES, H per heavy atom), CCDC kept as the reference until then. Provenance (temperature,
  R factor) exists only in the database, so one CCDC pass for the provenance side table may remain.
- **Z′ < 1 and multi-component (Q3): status only for now**, but multi-component crystals should eventually blend with
  Z′ > 1: a crystal is a set of units, each with its own molecule and conformer (identical molecules = today's Z′ > 1;
  different molecules = salts, solvates, cocrystals). Needs unequal unit blocks, per-unit molecule identity, and, for
  the FD, a unit-swap quotient among identical molecules only.
- **Symbol-only CIFs (Q5) are one case of a general problem:** structures saved with less symmetry than they have, e.g.
  P2₁/c saved in P1, "a common case". The general approach is a `find_symmetry` step: expand the file to the full cell
  (P1), detect the space group from the atoms (spglib, with an explicit tolerance, heavy atoms first), re-express in
  the standard setting, verify by rebuilding, and record agreement or disagreement with any declared symbol. This also
  covers generator output. Not yet designed in detail.
- **The 46 missing chunks (Q6): wait** for the new chain.
- **Standard setting (Q4):** "a good default for featurization loops but not necessarily required in any given
  workflow". So `to_standard_setting` is its own optional step, included in the featurization recipes (e.g.
  `csd_v1`) and not forced by `read`, `from_arrays` or the other steps; `canonicalize` still re-expresses (D1).
- **Full re-analysis (Q7):** "It should default to not doing the full re-analysis." `read(..., full=None)` by default:
  read only; the chain runs when a named recipe is passed.
